# 033 · 自动表情回复

日期：2026-11-02
状态：完成（2026-11-02）

## 目标

把「回复完成后自动发表情」接进 WebUI 的对话链路：`/api/chat` 在正文结束、`done` 之前追加第 6 种 SSE 事件 `emote`，落进会话事件流，历史重建时挂到 assistant 消息；前端在回复末尾渲染一张表情图。发不发、发哪张，由已安装的 `emote-pack-default` 插件的本地小模型（`suggest` 动作）判断，默认开启、可关。

## 范围

**做：**

- 事件模型五 → 六（05 S2 / S8）：`internal/session/events.go` 新增 `EventEmote`；`Event` 增加 `emote_name` / `emote_label` / `emote_file` / `emote_score` / `emote_none_score`（`omitempty`）；`Message` 增加可选 `emote`（`name` / `label` / `file` / `score`）；`Rebuild` 把 `emote` 挂到当前 assistant 消息；旧事件流照常解析。
- 选择器：新增 `internal/emote`（`Picker.Pick(ctx, contextText)`）——插件必须 `ready`；读插件生效设置（`auto_emote` 默认 `true`、`min_score` 默认 `0` 并 clamp 到 0–1）；调 `emote-pack-default` 的 `suggest`（`limit=3`，只取 top1）、超时 3 秒；语境空白视为无语境，超过 2000 字符取末尾 2000 字符；只认 `decision=emote` 且 top1 分数 ≥ `min_score`；失败 / 超时 / 不可解析一律静默返回「不发」。
- 接入：`internal/httpapi/chat.go` 的 agent loop 流与直通流都在这轮收尾时（写 `done` 之前）判断并追加 `emote`；只在该轮有正文、没有触发 `ask_user`、且本轮还没发过表情时发（一轮最多一条）；事件持久化到会话的 `io/context/messages.jsonl`。
- 前端：`app/js/chat.js` 把 `emote` 挂到当前 assistant 占位消息；`app/js/render.js` 在正文后、操作按钮前渲染表情图块（历史消息同样渲染）；图片按需 `POST /api/plugins/emote-pack-default/call`（`{"action":"show","arguments":{"name":…,"inline":true}}`）取 data URI，按 name 内存缓存，失败静默不渲染；`app/styles/app.css` 补样式与灯箱放大；设置页核对 boolean / number 控件可用。
- 文档：05 S2 六事件 + S8；`blueprint/02` 事件表与 `Message.emote`；`reference/http-api` SSE 表；`reference/plugin-manifest` 的设置实例；`designs/10` FE4；本单与索引。

**不做（后置）：**

- 不做多插件表情路由：固定只认 `emote-pack-default`。
- 不把表情图回灌模型上下文，不做多模态上下文。
- 不做用户手动选表情、表情收藏、表情包切换。
- 不改插件实现（v1.2.0 已带 `suggest` 与 settings），不改网关 provider 层事件（03 C2 不变）。
- 不做 `emote` 的独立 HTTP 查询端点：历史与重建都从消息里读。

## 关键决定

- **核心触发，不是插件自驱**（05 S8）：插件只有 `actions`，没有「回复完成」钩子；核心触发时插件只做纯函数 `suggest`，无状态、可卸载、失败隔离简单。
- **事件在 `done` 之前**（05 S2 / S8）：`done` 是收尾标记，`emote` 属于本轮回复；先写 `emote` 再写 `done`，流式与回放一致。
- **追加投影不变**：只多一种事件，旧五事件流仍可解析；`omitempty` 保证旧 JSONL 与旧客户端不破。
- **静默失败**（05 S8）：未就绪、`auto_emote=false`、`decision=none`、分数不达标、调用失败、3 秒超时、语境空白（TrimSpace 后为空）——一律不发事件，回复与落盘不受影响。
- **默认开、两档关**（05 S8、PL3 / PL4）：`auto_emote` 默认 `true`；软关改插件设置（不动插件本体、其它动作照常），硬关卸载 / 删除插件。设置存 `$GQY_HOME/plugin-settings/emote-pack-default.json`。
- **语境只取本轮用户消息**：不把助手回复再回灌；空白视为无语境（单个字符仍会尝试）。调用固定 `limit=3`，只取 top1。
- **图片不进 SSE**（05 S2）：事件只带元数据（名称 / 标签 / 文件 / 分数），data URI 由前端按需取并缓存，避免几百 KB 图片撑大事件流与日志。
- **只在有正文且未提问时发**：纯工具轮不发；触发 `ask_user` 等待作答的轮次不发。

## 验收

```bash
cd app
gofmt -l ./internal/...          # 应无输出
go vet ./...
go test ./...
go build ./cmd/gqy-server
node --check js/chat.js && node --check js/render.js && node --check js/settings.js
```

行为验收：

1. 插件就绪（`auto_emote` 默认）发一轮有正文的对话：SSE 在 `text` 之后、`done` 之前出现 `emote`，字段齐全（`emote_name` / `emote_label` / `emote_file` / `emote_score` / `emote_none_score`）；`io/context/messages.jsonl` 有同一条；`GET /api/sessions/{id}` 能读到消息 `emote`。
2. `PUT /api/plugins/emote-pack-default/settings` 设 `{"auto_emote":false}` 后再聊：无 `emote`，其余回复不变。
3. 卸载插件后再聊：无 `emote`，回复正常。
4. 调用失败 / 超时（插件慢或缺失）：回复照常结束，不报 5xx、无 `emote`。
5. 纯工具轮或触发 `ask_user` 的轮次：不发 `emote`。
6. 刷新 / 重开会话：表情图从 `message.emote` 渲染，图片按需取、命中缓存不重复请求。
7. 旧事件流（无 `emote` 的历史会话）照常重建；既有测试不回归。

## 留底

完成（2026-11-02）。独立验收（verifier，task-17）结论：功能链路无阻断、可交付。

- 真实 gqy-server e2e（临时 GQY_HOME + fake OpenAI 上游 + 端口 5197）：34/34 断言 PASS。SSE 顺序 `text → emote → done`，emote 字段为 `emote_name/emote_label/emote_file/emote_score/emote_none_score`；事件落 `io/context/messages.jsonl`，`GET /api/sessions/{id}` 重建 assistant `emote={name,label,file,score}`。

- 前端：`scripts/check-js.sh` 15 files OK；`chat.js` 挂当前 assistant、`render.js` 正文后渲染 `<figure class="msg-emote">`、按需 `show(inline)` 取图 + 内存缓存 + 失败静默；设置页 boolean/number 可用。未做浏览器截图回归（用 SSE 原文 + 落盘 + 重建 + 代码核对替代）。

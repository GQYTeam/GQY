# 018 · 支线采纳 UI 与轮末执行

日期：2026-11-02
状态：完成

## 目标

把 017 的采纳链路接到前端：`branch` 事件渲染成支线卡片，带「采纳进主线」按钮；同时修掉一个生产路径缺陷——主线单轮结束时不执行排队支线（支线要等下一次请求才跑）。

## 范围

**做：**

- `/api/chat` 响应头 `X-GQY-Goal`（有 active goal 时），前端据此调用采纳接口。
- `js/api.js`：`chatStream` 支持 `onGoal`；新增 `adoptBranch(goalID, branchID, summary)`。
- `js/chat.js`：`branch` 事件入 `placeholder.branches`；点击「采纳进主线」→ 调采纳接口 → 标记已采纳 → 重渲染。
- `js/render.js`：`branchHTML` 卡片（支线标记、原消息、支线回答、采纳按钮/已采纳态）。
- `js/styles`：支线卡片样式。
- `agent.Loop`：轮末（无工具调用、即将收尾）也 drain 排队支线（不注入采纳摘要）；生产路径从 sink 取 Branches（此前只有测试手动设 `Loop.Branches`，生产从不 drain——真 bug）。
- 生产路径集成测试：`internal/httpapi/agentloop_branch_test.go`（排队 → 轮末执行 → branch 事件 → 采纳 → 注入）。

**不做：**

- 支线多轮/带工具执行（后置）。
- 分叉会话落盘（后续施工单）。

## 关键决定

- **采纳是显式动作**：卡片按钮触发 `POST /api/goal/{id}/adopt`；前端不改主线上下文。
- **轮末只执行排队支线、不注入采纳**：主线已结束，注入无意义且会浪费「只注入一次」。
- **生产路径用 sink 的类型断言取 Branches**：每请求的 sink 天然绑定会话与 goal，避免全局可变字段。

## 验收

```bash
make check
cd app && go test -race ./...
node --check app/js/*.js
```

行为验收：

1. 主线运行中发消息 → `queued:true`，goal 队列可见。
2. 主线收尾前执行排队支线，响应里出现 `branch` 事件（含 `branch_id`、`output`）。
3. 采纳后下一次请求的模型 messages 含 `[支线已采纳，纳入主线考虑]` 摘要，且只注入一次。
4. 前端支线卡片可点「采纳进主线」，成功后显示「已采纳」且不再重复提交。
5. 无 active goal 时不出现支线卡片与采纳按钮。

## 留底

完成（2026-11-02）。落点全部实现；`gofmt`/`vet`/`go test ./...`（14 包）/`make check` 全绿；`node --check` 通过。

关键修复：

- **生产路径从不 drain 支线**：`agent.Loop.Branches` 字段只有测试会设，生产恒为 nil。改为 `Run` 内先取 `Loop.Branches`，为空则从 `sink` 类型断言 `Branches`（`agentSink` 已实现三方法）。
- **主线单轮结束时不执行支线**：原只在每轮开始 drain；现在轮末（无工具调用、收尾前）再 drain 一次，只执行排队支线、不注入采纳摘要。

验收方式调整（按项目主人要求「不要冒烟测试，永远保持生产」）：mock 冒烟资产（`scripts/e2e-mock/`、demo/smoke 脚本与 Makefile 目标）已移除；链路验证改为 `agentloop_branch_test.go` 的生产路径集成测试（真实 handler/loop/goal/session，仅模型来源用测试替身）。

偏差：前端未做多浏览器手动验收（无自动化 UI 测试）；分支卡片样式为最小实现。

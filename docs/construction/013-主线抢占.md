# 013 · 主线抢占（loop 内支线排队）

日期：2026-11-02
状态：完成（2026-11-02）

## 目标

把 011 留底里没落的最后一段补上：**agent loop 运行中**，goal active 时用户新来的消息不打断当前轮，而是进支线队列；当前轮结束后按队列处理（或留给用户显式 adopt）。011 只做了 HTTP 层的 pause/queue，这一单让 loop 自己认 goal 状态。

## 范围

**做：**

- `internal/agent`：`Loop.Run` 每轮开始前检查 goal 状态与支线队列——goal active 且有排队消息时，先把它们作为支线记录（记录来源：排队时间、目标轮次），不注入主线上下文。
- `internal/agent`：运行中收到的新消息不中断当前轮（`/api/chat` 的消息注入走队列），当前轮结束后：goal 仍在跑 → 支线逐条处理后回报摘要；goal 已结束 → 排队消息按普通对话处理。
- `internal/goal`：Queue/Drain 语义补强（入队幂等、出队标记 processed、支线事件写进事件流）。
- `internal/httpapi/chat.go`：`/api/chat` 在 goal active 时走「进队列 + 事件流记录」，返回明确的 queued 事件（不静默丢弃）。
- 测试：loop 内注入 → 进队列不打断 → 轮后处理；goal paused 时新消息走主线；goal completed 后队列消息按普通对话处理。

**不做（后置）：**

- 分叉会话落盘（session manifest 里的父会话/合并关系，归 014）。
- 自动 resume、多 goal 并行、支线权限隔离。
- 智能抢占策略（优先级/超时丢弃）——只做 FIFO。

## 关键决定

- **主线不被打断是硬约束**：loop 内只读 goal 状态 + 入队，绝不在轮中切上下文；支线处理发生在轮边界。
- **队列是事件流的一部分**：入队/出队都写事件（可重建、可审计），不只在内存。
- **FIFO 且幂等**：同一消息重复入队按消息 id 去重；Drain 只取未处理项。
- **goal paused/completed 不走队列**：paused 时用户消息正常进主线（用户主动暂停后就是在对话）；completed 后回到普通对话。

## 验收

```bash
make check
cd app && go test -race ./...
```

行为验收：

1. goal active 且 loop 运行中，新消息入支线队列，当前轮不中断；轮结束后支线被处理并回报摘要。
2. goal paused 时，新消息直接进主线（不进队列）。
3. goal completed 后，队列消息按普通对话处理。
4. 同一消息重复入队只处理一次（幂等）。
5. 入队/出队事件写进事件流，从事件流可重建队列状态。
6. `/api/chat` 在排队路径返回明确的 queued 事件，不静默丢弃消息。

- `running` 标记是进程内内存态，多实例/重启后不保留；重启后队列仍在 goal 里，由下一次请求触发处理。

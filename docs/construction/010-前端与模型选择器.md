# 010 · 前端与模型选择器

日期：2026-11-02
状态：完成（2026-11-02）

## 目标

把零构建前端骨架搭起来，并把模型选择器接上资料能力：`index.html` + 原生 JS 模块 + CSS 由 Go 静态托管；对话 / 设置 / 看板 / 用量 / 灯箱五个页面或浮层可用；五种 SSE 事件渲染成消息块；草稿 / 停止 / 重试与附件上传交互落地；`/v1/models` 扩展 `capabilities`，前端选择器支持搜索、过滤、分组、最近使用、默认标记与键盘导航，选择后立即生效。

## 范围

**做：**

- 零构建前端骨架：`index.html` + `js/*` + `styles/*`（FE1）。
- 五个页面 / 浮层：对话、设置、看板、用量、灯箱；外加初始化引导与关键词浮窗两个组件（FE2 / FE3）。
- 五种 SSE 事件（thinking / tool / text / question / done）到消息块的渲染；思考折叠、工具轨迹、ask_user 卡片、产物灯箱（FE4 / FE5）。
- 草稿 / 停止 / 重试交互（FE6）。
- 附件上传：拖拽 / 选择、预校验、进度与失败提示（FE7）。
- localStorage 只放 UI 偏好；服务端为真相；密钥只存服务端（FE8）。
- 模型选择器：MD5 交互 + MD2 的 capabilities 数据；`/v1/models` 扩展 `capabilities`（MD4）。

**不做（后续施工单 / 后置）：**

- TypeScript 化：01 D2 的开放项，本文不展开。
- 组件框架、构建链、服务端渲染：保持零构建。
- 语音唤醒词、浏览器自动化等新交互形态。
- 多用户、会话分享、云端同步。
- 会话全文检索、向量知识库界面。

## 关键决定

- **FE1**：零构建形态——`index.html` + 原生 ES 模块 + CSS，Go 静态托管，改完即刷新；JS 模块按职责拆（api / store / render / chat / settings / board / glossary / markdown / i18n / menu / onboarding / files），`theme.css` 承载暗色令牌。
- **FE2**：对话 / 看板两个视图，设置 / 用量 / 扩展 / 灯箱 / 引导为浮层；侧栏入口对话、看板、扩展、设置；Esc 先关浮层，再看板，最后回对话。
- **FE3**：页面职责与数据来源照 `blueprint/frontend.md` 3.2——对话走 `/api/chat`（SSE）与 `/api/sessions`；设置走 `/api/models`、`/api/tools`、`/api/plugins`、`/api/usage`、`/api/gateway/status`；看板与关键词浮窗走 localStorage。
- **FE4 / FE5**：五种事件渲染成消息块；thinking 默认折叠、tool 块带参数 / 输出 / 耗时 / 状态、text 增量追加、question 渲染 ask_user 卡片、done 显示用量与停止原因；断开未收到 done 时保留增量并标记不完整。
- **FE6**：草稿按会话存服务端；停止发停止信号、保留增量并标 `canceled`；重试以当前消息为界重新发起，旧回复折叠标记「被替代」。
- **FE7**：附件上传拖拽 + 选择双入口；前端预校验类型与大小；同名并发由服务端 O_EXCL 保证不覆盖；图片可预览、移除。
- **FE8**：localStorage 只放 8 个 UI 偏好键（theme / locale / reduceMotion / lastView / board / glossary / voiceEnabled / onboarded）；消息、草稿、产物、密钥一律不落 localStorage；设置页只显示 `api_key_set`。
- **MD2 / MD4**：`capabilities` 六字段（tool_call / vision / thinking / reasoning_effort / context_window / max_output）；`/v1/models` 的 `data[]` 扩展 `capabilities`，provider 模型条目携带、路由组 `group/<id>` 不携带；不返回密钥字段。
- **MD5**：选择器交互——搜索、按能力 / 供应商过滤、provider 与路由组分组、最近使用置顶、默认标记、↑↓ 回车 Esc 键盘导航、选择后立即生效；全部用零构建 JS 实现（无框架、无构建）。

## 落点

```
app/index.html
app/js/{api,store,render,chat,settings,board,glossary,markdown,i18n,menu,onboarding,files,modelpicker}.js
app/styles/{base,shell,chat,ui,pages,panels,media,settings,features,responsive,theme}.css
app/internal/httpapi/models.go     # 增量：/v1/models 带 capabilities
```

- 模型资料缓存与热更新属于后端资料域（13 MD3 / MD6），本单只消费 `/v1/models` 的 `capabilities` 字段；资料拉取与缓存按 13 的落点另排施工单。
- `modelpicker.js` 只依赖 `/v1/models` 一次请求拿全能力，不做服务端搜索。

## 验收

```bash
make check
cd app && go test -race ./...
```

行为验收：

1. 零构建：静态托管可用，修改 JS / CSS 后刷新即生效，无构建步骤。
2. 五种事件各渲染成对应消息块；非流式与流式渲染结果一致。
3. 思考块默认折叠可展开；工具轨迹显示参数 / 输出 / 耗时 / 状态；ask_user 卡片数字键与自定义答案都能回填。
4. 草稿切会话不丢；停止保留增量；重试旧回复折叠；附件拖拽 / 选择上传、预校验与失败提示可用。
5. localStorage 只含 8 个 UI 偏好键，无密钥与消息正文；设置页不出现明文密钥。
6. 模型选择器：搜索、能力 / 供应商过滤、分组、最近使用、默认标记、键盘导航、选择立即生效。
7. `/v1/models` 的 provider 模型条目带 `capabilities`，路由组条目不带；无任何密钥字段。

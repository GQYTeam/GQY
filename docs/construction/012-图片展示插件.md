# 012 · 图片展示插件实现

日期：2026-11-02
状态：进行中

## 目标

把 `gqy-plugins-ShowImages-default` 从「只有文档和图片」做成**真正可加载的插件**：manifest + stdio JSON-RPC 服务，GQY 侧能按 04 P3/P4 的常驻插件路径发现、加载、调用 `list` / `show` 两个动作。这是「各插件仓库」从示例资产变成可运行插件的第一步。

## 范围

**做：**

- `manifest.json`：id `show-images-default`、protocol `gqy-jsonrpc-v1`、command `["node","index.js"]`、cwd `.`、timeout_ms 10000、concurrency `concurrent`、actions `list` / `show`（JSON Schema）。
- `index.js`：换行 JSON-RPC 2.0——`initialize`（返回 ok/name/version）、`call`（分发 `list` / `show`）、`shutdown`；处理 stdin EOF 自退（04 P8 的最后一道防线）；错误用 `{error:{message}}` 返回。
- `list`：返回 13 张图片的 `{name, style, file}` 数组（名称与 `gqy-images/` 实际文件一致）。
- `show`：参数 `{name}`，返回 `{content, data_uri}`——`content` 是给人看的一句说明，`data_uri` 是 `data:image/png;base64,…`（读取对应 PNG）。
- `test/handshake.mjs`：本地握手测试——spawn `node index.js`，依次发 initialize → list → show → shutdown，断言回包 id 一一对应、`list` 返回 13 条、`show` 的 data_uri 以 `data:image/png;base64,` 开头；进程退出码 0。
- `package.json`：`scripts.test = "node test/handshake.mjs"`（不引入任何依赖）。
- `README.md` 增量：安装与自检步骤（`npm test`；GQY 侧把目录放进 `$GQY_HOME/plugins/show-images-default/` 后 `POST /api/plugins/show-images-default/load`）。

**不做（后置）：**

- 不做图片搜索/语义检索、不做在线下载图片。
- 不做 oneshot 模式（静态资产类插件适合常驻）。
- 不写跨仓库的 Go 集成测试（GQY 侧只用现有 echo 示例测试；本仓用握手脚本自证）。

## 关键决定

- **零依赖**：只用 Node 内置模块（`node:readline`、`node:fs`、`node:path`），不引第三方包，保证任何装了 Node 的机器可跑。
- **协议照 04 P4**：换行分隔 JSON-RPC 2.0，`id` 原样回传；不支持并发乱序（`concurrency: concurrent` 但实现是顺序处理，单请求足够快）。
- **图片只读不写**：`show` 只读 `gqy-images/`，不接受任意路径（防路径穿越：name 必须在清单里）。
- **大图说明**：`show` 返回 data URI 可能 1–2MB，属预期；`list` 不返回图片内容。

## 验收

```bash
cd gqy-plugins-ShowImages-default
npm test          # 或 node test/handshake.mjs
```

行为验收：

1. `initialize` 回 `{ok:true,name,version}`，`id` 与请求一致。
2. `list` 返回 13 条，`name`/`style`/`file` 与 `gqy-images/` 实际文件一一对应（含两个 11 号文件）。
3. `show` 传合法 `name` 返回 `data:image/png;base64,…`；传不存在 `name` 返回 `error.message`，不抛进程。
4. `shutdown` 后进程以 0 退出；关闭 stdin 时进程也能自退。
5. 非法 JSON 行不崩进程，回 `error` 继续服务。

## 留底

完成（2026-11-02）。`node test/handshake.mjs` 通过（initialize → list → show → show-inline → show-missing → shutdown，13 条清单、data URI 前缀、错误不崩进程、退出码 0 全断言）。

落点：本仓库新增 `manifest.json`、`index.js`、`package.json`、`test/handshake.mjs`，README 与 docs/README 增量（安装与自检）。

端到端验证（gqy-server 实际加载）：`POST /api/plugins/show-images-default/load` → ready；`/call list` 返回 13 条；`/call show` 返回文件与字节数。

偏差：

- `show` 未内联时只返回 `{name,style,file,bytes}`，`inline:true` 才带 `data_uri`——因为原生适配器只读 `result.content` 字符串，且 3MB 图片的 data URI 不应默认塞进模型上下文（原单写的「总是返回 data_uri」改为按需）。
- 端到端冒烟发现**运行时真 bug**：插件进程用 `exec.CommandContext(请求 ctx)` 拉起，HTTP load 请求结束、请求 ctx 取消时子进程被 SIGKILL（表现为 load 成功、随后 call 报 broken pipe）。已修 `internal/plugin/proc_{unix,windows}.go`（进程生命周期改由 Close 管），并补回归测试 `TestPluginProcessSurvivesLoadContextCancel`。

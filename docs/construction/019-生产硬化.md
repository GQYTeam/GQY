# 019 · 生产硬化

日期：2026-11-02
状态：完成

## 目标

按「永远保持生产」的标准补三类硬化：**上游超时**、**关闭时回收插件进程**、**配置校验补强**，并把失败语义归一（超时不再退化成笼统的 no_candidate）。

## 范围

**做：**

- `settings.upstream_timeout_s`（默认 120，1–3600）：网关每次上游调用（Complete/Stream）按热更新快照加整体超时。
- 超时/连接失败归一：`context.DeadlineExceeded` → `upstream_timeout`（可重试，504）；连接失败 → `connection_error`。
- 全部候选失败时若最后错误是超时/连接错误，直接返回该错误（而不是笼统的 `no_candidate`）。
- `plugin.Manager.Close(ctx)`：关闭全部已加载插件并回收进程组（P8），幂等、错误聚合。
- `gqy-server` 退出路径（信号与异常退出）都调用插件关闭。
- 配置校验补强：`base_url` 必须以 `http://` / `https://` 开头；`upstream_timeout_s` 范围校验。
- 测试：网关超时（1s 生效、错误码与可重试）、插件 Close 全量卸载 + 幂等、配置校验正反例。

**不做：**

- 上游重试退避策略调整（仍按 R3 的 max_attempts/冷却）。
- 熔断、限流窗口持久化。
- 前端错误展示细化。

## 关键决定

- **超时按请求快照计算**：`settings` 热更新后新请求立即用新超时，无需重启。
- **超时优先于 no_candidate**：只在上游超时/连接失败时返回具体错误；多候选混合失败仍返回 no_candidate。
- **插件关闭在 HTTP 停止之后**：先让在途请求结束，再回收插件进程组，避免半途杀进程。
- **校验宁严不松**：`base_url` 非 http(s) 直接拒绝，避免启动后才发现配置错误。

## 验收

```bash
make check
cd app && go test -race ./...
```

行为验收：

1. `upstream_timeout_s=1` 时，上游卡死 1s 返回 `upstream_timeout`（可重试），不是 `no_candidate`。
2. `upstream_timeout_s` 为 0 或 >3600 时配置校验失败；`base_url` 非 http(s) 时校验失败。
3. 服务退出时所有已加载插件被卸载（实例表清空），重复关闭幂等。
4. 配置/状态接口仍不泄漏 `api_key`（既有测试保持通过）。

## 留底

完成（2026-11-02）。落点全部实现；`gofmt`/`vet`/`go test ./...`（14 包）/`make check` 全绿。

测试：`TestUpstreamTimeoutComplete`（1s 超时生效、`upstream_timeout` 可重试、耗时 <3s）、`TestManagerCloseAll`（两个插件全卸载、重复 Close 幂等）、`TestSettingsAndBaseURLValidation`（upstream_timeout_s 0/5000 拒绝、ftp:// base_url 拒绝、60 通过）。

偏差：

- 超时是「一次上游调用」的整体超时，不区分首字节/流式空闲；流式挂起按整体超时处理（后续如需「流式空闲超时」另开施工单）。
- 插件关闭只遍历已加载实例；discovered/failed 实例不涉及进程，无需回收。

# 026 · 记忆子系统

日期：2026-11-02
状态：施工中

## 目标

给 GQY 加第一个**长期记忆**能力：能装、能查、能写、能被 agent 用、能在控制台看见。数据来自旧版 GQY v0.7.0 的 `<user>/<persona>/memory/memory.db`（结构见 `docs/reference/legacy-home.md`），但子系统本身不依赖迁移也能独立工作。

依据：`18-记忆与迁移.md` MEM1–MEM8；`blueprint/memory.md`。

## 范围

**做：**

- `app/internal/memory`：记录模型、JSONL 存储、内存索引、召回打分、原子追加、单目录多库。
- `storage.EnsureRoot` 增加 `memory/` 目录（0700）。
- `app/internal/httpapi/memory.go` + 路由：`/api/memory*` 九个端点（见蓝图 §3）。
- 核心工具 `memory_recall` / `memory_remember`，在 `cmd/gqy-server` 注册。
- 测试：存储往返、幂等、召回确定性、CJK 分词、重要度/衰减、归档修订、HTTP 端点、工具执行。

**不做（后置）：**

- 自动抽取 / 自动蒸馏记忆（先跑通读写与迁移）。
- 在线 embedding（旧库向量只读复用，不新算）。
- 写入并发跨进程、分片索引、加密存储。
- 控制台页面（另开 026 之后的前端单）。

## 关键决定

- **文件即真相**：JSONL 追加，无 SQLite（零依赖硬约束）。索引在内存重建，进程退出即丢。
- **读不写盘**：召回不更新 `recall_count`，读路径零副作用，保证同输入同输出可测。
- **多库共存**：`memory/<persona>/`，默认 `default`；HTTP 与工具都可指定 persona，缺省 `default`。
- **脱敏在视图层**：`owner_principal` 掩码、正文超 4000 字截断，都不改存储原值。
- **损坏容错**：JSONL 半行跳过并记 `load_warnings`，不阻塞启动。

## 留底

完成（2026-11-02）。落点与计划一致：`app/internal/memory`（memory/store/recall/views + 三个测试文件，66 用例）、`httpapi/memory.go`（九个 handler）+ `server.go` 九行路由、`tool/memory.go` 两个核心工具、`storage.EnsureRoot` 加 `memory/`。`gofmt -l` 无输出、`go vet` 通过、`go test ./...` 16 包全 ok、`-race` 通过。

端到端（临时 home + 真迁移数据）：`GET /api/memory` 返回 `personas:[{id:"default",counts:{facts:347,episodes:2054,revisions:47,evicted:0}}]`；`POST /recall` 同参两次逐字一致；写入后立即可召回；归档后从召回消失且 `revisions` 留审计行。

偏差：

- `load_warnings` 只在内存与 API 返回，不写 `meta.json`（守住「读路径零写盘」）。
- `meta.json` 仅首次写入时创建。
- 空查询返回空；`lexical=0` 且无向量不进结果。
- 列表排序：`updated_at` 降序 → `id` 降序（revisions 按 id 升序）。
- `visibility=normal` 默认不进列表与召回。
- 控制台页面未做（后置）。

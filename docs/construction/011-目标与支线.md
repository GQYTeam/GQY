# 011 · 目标与支线

日期：2026-11-02
状态：进行中

## 目标

把 goal 状态机与主线 / 支线机制接起来：goal 挂在会话上，主线优先不被打断；新指令进支线（同会话排队或分叉会话）；支线回报后只有显式采纳才合并；goal 可 pause / resume，resume 从事件流投影重建；吸收 claude-code 走查的「独立评估器三态判定 + 错误分类（不可恢复 → blocked、暂时性 → 重试 N 次后 paused）」。

## 范围

**做：**

- goal 状态机：`active` / `paused` / `completed` / `blocked` + `max_rounds`；goal 挂会话与事件流（GL1）。
- 主线优先：新指令不打断主线，进支线（GL2）。
- 支线两种形态与边界：同会话排队消息 vs 分叉会话（GL3）。
- 支线回报与合并：显式采纳才合并，不自动覆盖主线（GL4）。
- pause / resume 与事件流重建（GL5）。
- 与 ask_user 的关系：挂起等答案时其他消息进支线（GL6）。
- 独立评估器三态判定（未达成 / 达成 / 不可能）与错误分类（不可恢复 → blocked、暂时性 → 重试 N 次后 paused）。

**不做（后续施工单 / 后置）：**

- 多 goal 并行、goal 之间的依赖与编排（DAG）。
- 自动 resume 调度、定时触发。
- 智能抢占 / 新指令紧急度判断：默认全部进支线。
- 支线权限与配额隔离：单机单用户，沿用 11 的信任模型。
- goal 跨会话迁移与落盘细节升级（形状留给 blueprint/session 后续补齐）。

## 关键决定

- **GL1**：goal 字段 `id` / `title` / `state` / `max_rounds` / `created_at`；状态机 `active ⇄ paused`、`active → completed`（达成）或 `active → blocked`（轮数用尽 / 依赖缺失）；`paused` / `blocked` 可重新 `active`；`max_rounds` 用尽 → `blocked` 并报告未完成原因。
- **GL2**：goal 处于 `active` 且 loop 运行中时，用户新指令不打断主线；新指令进支线（同会话排队或独立分叉会话），主线继续当前轮。
- **GL3**：支线两形态——轻量指令走「同会话排队消息」，当前轮结束后处理；独立任务走「分叉会话」，复用 05 S1/S2 的会话单元与事件流投影，记父会话 id 与合并关系。
- **GL4**：支线完成后回报一句话摘要；只有主线显式采纳（用户确认或 agent 决定）才把支线结果写进主线上下文；不自动合并、不覆盖主线事实与工具轨迹。
- **GL5**：goal 可 `pause` / `resume`；pause 冻结主线 loop，支线可继续；resume 从主线事件流投影重建上下文（05 S2），继续最后一轮；不另存上下文副本。
- **GL6**：主线遇 ask_user 暂停等答案，loop 挂起在 `question`；答案经数字键 / 自定义答案回填主线；此时其他消息默认进支线；用户取消或超时未答，主线保持暂停、goal 状态不变。
- **走查借鉴（claude-code goal）**：完成判定交给独立评估器——每轮后小模型三态判定「未达成 / 达成 / 不可能」，条件写成可验证检查（如「命令退出 0」），评估器不跑工具、只看已展示在对话里的证据。
- **走查借鉴（错误分类）**：不可恢复错误（认证失败 / 额度耗尽 / 上下文溢出 / 模型不可用）→ `blocked`；暂时性错误 → 自动重试 N 次（默认 3）后 `paused`；后台任务 / 支线未结束时跳过该轮评估，避免对没完成的活下结论。

## 验收

```bash
make check
cd app && go test -race ./...
```

行为验收：

1. `active` 主线运行中发新消息：主线继续，新消息进排队或分叉，主线上下文不含新指令。
2. 排队消息在当前轮结束后被处理；分叉会话独立记录事件流；支线合并只经显式采纳。
3. `pause` 后主线 loop 冻结；`resume` 从事件流重建到最后一轮并继续。
4. ask_user 挂起时：答案回填主线，其他消息进支线；取消后主线保持暂停。
5. `max_rounds` 用尽 → goal `blocked`，并报告未完成原因。
6. 独立评估器三态判定正确；不可恢复错误 → `blocked`，暂时性错误重试 3 次后 → `paused`。
7. goal 状态与支线关系在会话列表 / 状态接口可见。

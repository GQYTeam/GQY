# 008 · 评测

日期：2026-11-02
状态：完成（2026-11-02）

## 目标

把评测子命令 `gqy-eval` 做成可运行闭环：读配置与用例集 → 生成三维矩阵 → 对每个「用例 × 组合 × 重复」跑单次对话循环（渲染 → 请求 → 工具执行 → 回填 → 最终答案）→ 规则判定 + 模型裁判 → 全量落盘（runs.jsonl / trace / report）→ 支持回放。评测复用 gateway / tool / plugin，不占 `gqy-server` 并发额度（01 D4）。

## 范围

**做：**

- `gqy-eval` CLI：`-config` / `-out` / `-dry-run` / `-replay` / `-filter`（E1）。
- 三维矩阵 prompt / schema / return 与 single / pair / full 三阶段、round / axis 标签（E2）。
- 用例集形状（输入 + 期望行为）与版本冻结（E3）。
- 单次对话循环：渲染 → 请求 → 工具执行 → 回填 → 最终答案；超时 / 超轮记 `not_converged`（E4）。
- 判定：规则五类 + 模型裁判补充；gateway_error 与 exec_error 分开（E5，复用 03 C9）。
- 落盘目录树与 `runs.jsonl` 字段（E6）。
- 回放：从 trace 不发真实请求（E7）。
- 报告七项与指标（E8）。
- 成本与并发控制：组间小并发、组内串行、限流退避重试落盘、工具超时不重试、增量模式（E10）。

**不做（后续施工单 / 后置）：**

- 契约测试改造：契约测试管链路正确（假上游 / 假插件），评测管能力正确，本单只做评测（E9 分工不变）。
- 真实多轮基准集：先跑通机制，基准集数据后置。
- 模型裁判成为主判定：规则判定仍是主判定，模型结果单独记录。
- 跨轮自动比较、自动写回线上配置。
- 并行压测与大规模并发；评测服务化 / HTTP API。

## 关键决定

- **E1**：`gqy-eval` 是独立子命令，跑完即退；复用 `gateway` / `tool` / `plugin`，不启动 HTTP 服务、不写会话。
- **E2**：三维矩阵取值显式枚举在配置里；`single` 固定两维扫第三维、`pair` 两两组合、`full` 全组合 N≥5；每轮打 `round` / `axis` 标签；`-filter` 按维度筛选、`-dry-run` 只打印矩阵与用例数。
- **E3**：用例是「输入 + 期望行为」，不做逐字相等；`expect` 五条件（should_call / tool / arg_contains / final_contains / must_not_call）缺省不判该项；用例集与判定器带版本，一轮内冻结。
- **E4**：单次对话循环固定五步：渲染 → 请求（走 03 C1/C2 与 02 网关）→ tool_call 则执行并回填 → 最终答案进判定 → 超时 / 超轮记 `not_converged` 仍进判定；每步全量录制。
- **E5**：规则判定优先（五条规则）；模型裁判只用于主观项，固定裁判模型、温度 0、固定模板，结果单独记录标注来源；`gateway_error`（模型侧失败）与 `exec_error`（工具执行失败）分开统计，复用 03 C9 错误归一。
- **E6**：落盘目录 `configs / runs / trace / report / best`；`runs.jsonl` 一行一条，字段齐全、带版本（模型 / 网关 / 用例集 / 判定器 / 插件 / 适配器）、写前脱敏；禁止跨轮比较，`best/current.json` 只由完整轮次写入。
- **E7**：`-replay <trace 目录>` 用录制响应重放，不发真实模型请求；产出同样目录并标 `replay: true`；用于验证判定器 / 渲染改动，失败可复现。
- **E8**：`report.md` 固定七项（配置摘要、矩阵汇总表、单因素对比、交互效应、反例清单、结论建议、成本）；指标含调用决策 / 工具选择 / 参数合规 / 返回值利用 / 端到端成功率 / 平均轮次与 token / 延迟 / 稳定性。
- **E10**：按配置分组小并发、组内串行；对 provider 限流退避重试并落盘标 `retry_of`；工具 / 插件执行超时视为失败样本不重试；成本控制用 single / pair 快筛、full 才放大，支持增量只跑变化维度。

## 落点

```
app/internal/eval/{config,cases,matrix,engine,runner,host,judge,result,recorder,replay,report}.go
app/cmd/gqy-eval/main.go
```

- `host` 注册核心工具与真实插件（工具名 `pluginID__action`），复用 `tool` / `plugin` 运行时。
- 评测输出目录由 `-out` 指定，与 `$GQY_HOME` 运行态分开。

## 验收

```bash
make check
cd app && go test -race ./...
```

行为验收：

1. `-dry-run` 只打印矩阵与用例数，不发请求；`-filter prompt=basic` 只跑匹配组合。
2. single 阶段固定两维扫第三维，`runs.jsonl` 的 `round` / `axis` 标签正确。
3. 一次「请求 → 工具执行 → 回填 → 最终答案」全链路跑通，runs.jsonl / trace / report / cases 快照齐全。
4. 五条规则各有一个通过与一个反例；模型裁判结果单独记录且标注来源。
5. `-replay` 从 trace 回放不发真实请求，判定与录制一致。
6. 故障注入 empty / error / timeout / slow 各产出对应 `status`；`gateway_error` 与 `exec_error` 分开计数。
7. runs.jsonl 与 trace 无 api_key / token / secret 明文。

# 005 · 会话与产物

日期：2026-11-02
状态：完成（2026-11-02）

## 目标

把 002 的 `/v1/chat/completions` 直通能力接到会话层：会话创建 / 列表、消息事件流 JSONL 落盘（真相源）、五种 SSE 事件（thinking / tool / text / question / done）对应的 `/api/chat` 内部协议、草稿 / 停止 / 重试、附件上传落盘、产物灯箱数据，并把 `gqy-clean` 子命令接上 TTL 清理。

## 范围

**做：**

- 会话创建、列表、切换（S1）。
- 消息事件流 JSONL 落盘为真相源；五种事件按序投影成消息（S2、C2、`blueprint/session.md`）。
- `/api/chat` 内部五事件 SSE 协议（thinking / tool / text / question / done）。
- 草稿按会话保存、停止保留增量、重试不覆盖历史（S4）。
- 附件上传落盘与产物灯箱数据（S3）。
- `gqy-clean` 子命令接上 TTL 清理（S6、ST7）。

**不做（后续施工单）：**

- agent loop 的工具调用编排（006）。
- 知识库 / 记忆（对应主题后置）。
- 向量检索 / 会话全文检索。
- 多用户、会话分享、云端同步（05 已后置）。

## 关键决定

- **会话 = 事件流投影**：消息不单独存储；`io/context/messages.jsonl`（事件流）是真相源，任何界面从事件流重建消息，崩溃后重建到最后一个完整回合（S2、ST2、ST5）。
- **目录用 05 S5 + 09 ST**：`sessions/<SESSION_ID>/{manifest.json, tmp, logs, io, scripts}`；manifest 原子写；工具日志按日期分文件（ST3、ST4）。
- **五种 SSE 事件字段照 `blueprint/session.md`**：thinking（delta）、tool（tool_name / phase / arguments / output / duration_ms / status）、text（delta）、question（options / allow_custom）、done（usage / stop_reason）；`stop_reason` 与 `usage` 形状沿用 03 C2。
- **`/api/chat` 不旁路网关**：与 002 的 `/v1/chat/completions` 共用同一 provider 事件流，只把输出投影成五事件 SSE（02 R8、03 C2）。
- **`gqy-clean` 复用 storage**：TTL 从 `manifest.json` 的 `cleanup_policy` 读；删除前核对目标路径在 `$GQY_HOME` 内，防越界（S6、ST7）。

## 验收

```bash
make check
cd app && go test -race ./...
```

行为验收：

1. 创建会话返回 `session_id`，会话列表可见；切换会话上下文正确。
2. `/api/chat` 流式输出五种事件且顺序稳定；同一回复的事件落 `messages.jsonl`；从事件流重建消息与流式一致（非流式 = 流式拼接）。
3. 草稿切会话不丢；停止后已产出增量保留并标 `canceled`；重试不覆盖历史，旧回复折叠。
4. 同名附件并发上传不覆盖（O_EXCL），文本注入 / 图片多模态 / 二进制落盘路径正确。
5. 产物灯箱数据正确：`manifest.artifacts` 只记最终产物，中间产物在 `tmp/generated/`。
6. `gqy-clean --expired` 只清过期会话，未到期不动；越界路径被拒绝。
7. 事件流与日志不含密钥 / token / 正文（G6）。

# 001 · 骨架与配置快照

日期：2026-11-02
状态：进行中

## 目标

从零恢复可运行的 Go 服务骨架：`gqy-server` 能启动、读配置、建数据根、提供 `/v1/models`，并对 `/api`、`/v1` 提供统一的鉴权与限流。后续施工单在此基础上接网关、协议翻译与插件。

## 范围

**做：**

- `app/` 下重新建立 `module gqy`（Go 1.22，标准库）。
- `internal/config`：启动环境变量 + 三份 JSON 配置 → 不可变快照；校验、原子切换、手动重载与 SIGHUP（CF1、CF4、CF5、CF7、CF9）。
- `internal/storage`：`$GQY_HOME` 目录与权限、原子写（ST1、ST4、ST6）。
- `internal/gateway`：模型目录与三种模型解析（R1、R2、R6、C11），暂不发起上游请求。
- `internal/httpapi`：路由、访问令牌（Bearer / cookie）、入口限流、`/healthz`、`/v1/models`、`/api/auth`、`/api/config`、`/api/config/reload`、`/api/gateway/status`（A1–A4、A9、R8）。
- `cmd/gqy-server`：装配、优雅关闭、SIGHUP 重载。
- 单元测试覆盖配置校验与回滚、模型解析、鉴权、限流、重载端点。

**不做（后续施工单）：**

- 上游 provider 调用、失败转移、冷却、配额、会话亲和（R1–R5 的运行时部分）。
- OpenAI / Anthropic / Gemini 的请求与流式翻译（C1–C10）。
- 文件监视 fsnotify（CF6）；本单只有手动重载与 SIGHUP。
- 会话、工具、插件、评测、前端。
- `gqy-clean` / `gqy-eval` / `gqy-import` 子命令。

## 关键决定

- 配置读取与校验只放在 `config` 包，启动与重载共用 `Build`（CF4、CF10）。
- 快照用 `atomic.Pointer` 整份替换；重载失败保留旧快照（CF5）。
- 读取接口只暴露 `api_key_set`，快照里的明文密钥不参与任何 JSON 输出（R5、CF8、A8）。
- 未设置令牌且监听非回环地址时，请求仍按 A3 拒绝非本机来源；启动日志给出警告。
- 限流在鉴权外层，按连接对端 IP 的分钟固定窗口计数（A4、A5）。

## 验收

```bash
cd app
gofmt -l ./cmd ./internal
go vet ./...
go test ./...
go build ./cmd/gqy-server
```

行为验收：

1. 无配置文件启动成功，`/healthz` 返回 `ok`。
2. `providers.json` / `routing.json` 写合法内容后重启，`/v1/models` 按 C11 形状列出 provider 模型与 `group/<id>`。
3. 写入非法 JSON 或重复 group id，`POST /api/config/reload` 返回 422，版本号不变，旧配置继续服务。
4. 设置 `GQY_AUTH_TOKEN` 后，无令牌访问 `/v1/models` 返回 401；Bearer 与 cookie 均可通过。
5. `rate_limit=2` 时第三分钟内请求返回 429 且带 `Retry-After`。
6. 状态与配置接口不出现 `api_key` 明文，只出现 `api_key_set`。

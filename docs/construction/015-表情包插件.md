# 015 · 表情包插件

日期：2026-11-02
状态：完成（2026-11-02）

## 目标

把 `gqy-plugins-EmotePack-default` 做成**可加载的常驻插件**：24 张 512×512 静态表情 + 4 个 GIF 动图包，按 04 P3 / P4 / P8 / P11 的常驻插件路径被发现、加载、调用 `list` / `show` / `match` 三个动作。在 012 图片展示插件之后，验证两条新做法：**清单由数据文件驱动**、**插件内做确定性情绪匹配**；并第一次让插件处理 GIF 动图。

## 范围

**做：**

- `manifest.json`：id `emote-pack-default`；name `表情包插件`；version `1.0.0`；protocol `gqy-jsonrpc-v1`；command `["node","index.js"]`；cwd `.`；timeout_ms 10000；concurrency `concurrent`；actions `list` / `show` / `match`（JSON Schema）；provides / requires 空数组。字段按 04 P3 与蓝图 manifest 全字段表。
- `index.js`：换行 JSON-RPC 2.0——`initialize`（回 `{ok:true,name,version}`）/ `call`（`{action, arguments}`，结果取 `result.content`）/ `shutdown`（回 ok 后退出 0）；stdin EOF 自退（04 P8 最后一道防线）。错误码分层：非法请求对象 `-32600`、未知方法或动作 `-32601`、参数形状不合法 `-32602`、业务 / 资产错误 `-32000`、非法 JSON 行 `-32700`（`id` 回 null）；全部只回错误、不崩进程。
- `list`：启动时读 `data/assets.json` 当清单，返回 `{count, emotes[], motions[]}`（`count` = 表情 + 动图合计 28）；每条含 `name` / `label` / `tags` / `file` / `bytes` / `width` / `height`，动图另含 `frames` / `frame_ms` / `duration_ms` / `note`。`bytes` 现读磁盘不缓存；每次调用前都校验清单与磁盘一致，缺失、多余、空文件、魔数与扩展名不符、尺寸不符都报清晰错误。资产目录里只允许清单登记的文件；系统元数据（`.DS_Store`、`.localized`、`Thumbs.db`、`._*`）忽略，其余多余文件或子目录报错。
- `show`：参数 `{name, inline?}`；只查清单（含清单里的 file 路径），不接受任意路径（防目录穿越）；返回 `{name, label, media, file, bytes}`，`media` 区分 `image/png` / `image/gif`；`inline:true` 追加 `data_uri`，PNG 用 `data:image/png;base64,`、GIF 用 `data:image/gif;base64,`；不存在返回含「不存在」的 error，不抛进程。
- `match`：参数 `{query, limit?}`；只在 24 张表情上打分（动图用 `show` 按名称取），按 label / tag 确定性打分降序，同分按清单顺序，`limit` 默认 3、上限 24；返回 `{query, matches:[{name,label,score,file}], hint?}`；全 0 分返回空数组 + `hint`（「没有匹配的表情，可用 list 查看全部」）。
- 测试：manifest 与资产校验（24 + 4 条、name 唯一、文件存在非空、PNG 512×512、GIF 魔术与逻辑屏尺寸、目录无未登记文件）+ 握手测试（initialize → list → show → match → 错误路径 → shutdown，另验关 stdin 自退）。`package.json` 的 `test` 串起两者，零依赖。
- 文档：仓库 `README.md`、`docs/README.md`、本施工单、org 根 `README.md` 仓库地图登记一行。

**不做（后置）：**

- 不做语义检索 / 向量匹配：`match` 只做确定性标签打分，不打模型、不联网。
- 不做转码与导出：PNG / GIF 已是成品，不转 WebP / MP4，不打包微信表情包。
- 不做图片编辑 / 生成：插件只读资产，不写文件。
- 不做 oneshot 模式：静态资产类插件适合常驻（同 012）。
- 不写跨仓库 Go 集成测试：本仓用 `npm test` 自证，GQY 侧用 `/api/plugins/{id}/call` 冒烟。

## 关键决定

- **清单由数据文件驱动（与 012 的第一处差异）**：012 把 13 张图硬编码在 `index.js` 里；本单以 `data/assets.json` 为唯一索引，三个动作全部从它派生——加表情只改数据、不改代码。代价是清单与磁盘可能不一致，所以启动读、调用时校验，并用测试守住「无未登记文件」。
- **新增 `match`（与 012 的第二处差异，012 只有 list / show）**：按情绪找表情是本插件的主要用法；用确定性打分而非模型，保证可复现、离线、可测试。只对 24 张静态表情打分，动图不参与（按名称用 `show` 取）。分数分档写进文档与测试：「label 完全相等 +100、tag 完全相等 +60、label 包含 query +40、query 包含 label +30、tag 与 query 互相包含各 +20」；全等是包含的特例，同一项只取最高档、不叠加。「累」应最高命中 `05-困倦` 或 `09-打哈欠`，「生气」应精确命中 `13-生气`。
- **含 GIF 动图（与 012 的第三处差异，012 全是 PNG）**：`media` 字段区分 PNG / GIF，`inline` 时 base64 前缀不同。最大动图 5,597,005 B（约 5.6 MB，512×512、72 帧），data URI 约 7.5 MB，已接近蓝图规定的 stdio 单行 8 MB 缓冲上限；因此 `inline` 必须显式开、默认只回文件信息，文档建议「只对单张表情按需 inline，动图慎用」——沿用 012 留底的教训。
- **协议照 04 P4**：换行分隔 JSON-RPC 2.0，`id` 原样回传；不支持并发乱序（`concurrency: concurrent` 但实现顺序处理，单请求足够快）。
- **回收照 04 P8**：stdin EOF 自退是协议要求的第一层，保证 GQY 异常退出不残留孤儿进程。
- **工具注册照 04 P11**：三个动作注册成 `emote-pack-default__list` / `__show` / `__match`；默认不注入模型，`GQY_ENABLE_EXTERNAL=1` 或运行时开关打开才进 agent 工具列表。
- **零依赖**：只用 Node 内置模块（`node:readline`、`node:fs`、`node:path`），不引第三方包（同 012）。
- **命名口径以数据为准**：`motions/表情包-微信240-24态.gif` 实测 240×240、6 帧、450ms/帧、共 2.7s，文件名里的「24 态」与内容不符；文档与清单按事实写，不以文件名推断。

## 验收

```bash
cd gqy-plugins-EmotePack-default
node --check index.js
npm test
```

行为验收：

1. `initialize` 回 `{ok:true,name:"emote-pack-default",version:"1.0.0"}`，`id` 与请求一致。
2. `list` 返回 24 条表情 + 4 条动图；每条 `file` 存在、`bytes` 与实际一致；尺寸与帧信息与 `data/assets.json` 一致（按清单顺序：24 / 72 / 6 / 6 帧，520 / 400 / 620 / 450 ms/帧）；资产目录里出现 `.DS_Store` 等系统元数据时忽略、不报错，其它未登记文件则报错。
3. `show` 传合法 name 返回正确 `media` 且无 `data_uri`；`inline:true` 返回 `data:image/png;base64,` 或 `data:image/gif;base64,` 前缀；不存在 name 返回含「不存在」的 error，进程继续服务。
4. `match` 传「累」最高分命中 `05-困倦` 或 `09-打哈欠`；传「生气」精确命中 `13-生气`；传无关键词返回空 `matches` + `hint`；`limit` 生效。
5. `shutdown` 后进程 0 退出；只关 stdin 也能在 5s 内自退；非法 JSON 行回 `-32700`、参数形状不合法回 `-32602`、非法请求对象回 `-32600`，进程继续服务。
6. GQY 侧端到端：`POST /api/plugins/emote-pack-default/load` 成功 → `GET /api/plugins` 中该插件 `state=ready`、`actions` 三项 → `/call list` 返回 24 + 4 条 → `/unload` 后实例消失。

# 18 · 记忆与迁移

依据：`00-设计理念.md` G6（密钥与正文不进仓库、不进日志）；`09-存储.md` ST1/ST2/ST4/ST7；`15-一次性插件.md` NX1–NX7；`05-会话与产物.md` S2（事件流是消息的真相源）。
外部输入：旧版 GQY v0.7.0 的 `GQY_HOME` 导出（结构见 `docs/reference/legacy-home.md`，由真实备份 `gqy_backup_20261005_180648` 反推）。

## 范围

**做：**

- 记忆子系统：事实 / 片段 / 修订 / 被挤出上下文四类记录，文件级 JSONL 存储，索引在内存重建。
- 召回：确定性词法打分 × 重要度 × 强度 × 时间衰减；记录自带向量时可选余弦。
- HTTP 只读接口 + 写入接口 + 两个 agent 工具 + 控制台「记忆」页。
- 迁移：把旧版导出迁到新 `$GQY_HOME`，做成一次性插件（NX 形态），默认 dry-run、幂等、脱敏、可回滚。

**不做（后置，各自单开施工单）：**

- 不内置 embedding 模型：只在记录已带向量时做余弦，不给查询在线算向量。
- 不在对话后自动蒸馏记忆：先把手写与迁移写入跑通，自动抽取另立。
- 不迁入产品能力：知识库检索、图库、记账、平台消息只按资产归档，不接 UI 与检索。
- 不做多用户鉴权：多个人格库共存，但不按 principal 做权限校验。
- 不写 SQLite：零第三方依赖是硬约束（`01-架构.md` D1/D2）。

## 决定

### MEM1 · 文件即真相，索引在内存重建

记忆的真相源是 append-only JSONL：写只追加，不原地改。启动时读入内存建索引（按 id、关键词、向量），进程退出即丢索引，下次重建。对齐 ST2「派生可重建」与 ST4「原子写」。

### MEM2 · 目录与文件

```
$GQY_HOME/memory/
  meta.json                    # 库级元信息
  personas.json                # 人格清单（含旧版 subsystems 开关）
  <persona>/
    facts.jsonl                # 长期陈述
    episodes.jsonl             # 对话片段
    revisions.jsonl            # 修订审计
    evicted.jsonl              # 被挤出上下文的原始轮次
```

`<persona>` 与旧版 `<user>/<id>` 对齐，默认 `default`。目录由 `storage.EnsureRoot` 一并创建（0700）。

### MEM3 · 记录模型

- **facts**：长期陈述。`memory_type` 取 `fact` / `preference` / `self` / `correction` / `task` / `relationship`；`truth_status` 取 `accepted`（已确认）/ `reported`（转述未核实）。
- **episodes**：对话片段。`retention` 取 `short_term` / `long_term`；长片段带 `source_key` 去重，可被提升为 facts（`promoted_at`）。
- **revisions**：`memory_id` + 旧内容 + 新内容 + 来源片段 id，只增不改。
- **evicted**：被上下文挤出策略淘汰的原始轮次（role/content/时间/会话 id），是召回的最后一道兜底。
- 公共字段：`visibility`（原值迁移保留）、`owner_principal`、`subjects`、`tags`、`importance`（1–5）、`confidence`、`strength`、`recall_count`、`last_recalled_at`、`last_decay_at`。字段表见 `blueprint/memory.md`。

### MEM4 · 召回打分

`score = lexical × importanceFactor × strength × recency`：

- `lexical`：查询词命中率（0–1）。CJK 用双字滑窗，ASCII 按词，大小写不敏感；空查询直接 0。
- `importanceFactor = 0.5 + importance/10`（importance 1–5 → 0.6–1.0）。
- `recency = max(0.3, exp(-ageDays/30))`，`ageDays` 按 `updated_at` 算。
- 记录带向量且查询带向量时：`score = 0.65×lexical + 0.35×cosine`（余弦裁到 0–1），`lexical` 仍做下限保护。
- 排序：score 降序 → `updated_at` 降序 → `id` 升序，保证同输入同输出（可测试）。
- 默认只召回 `status=active`；`include_archived=true` 才带归档。

**为什么向量不优先**：旧库向量来自本地 `bge-small-zh-v1.5-int8`，新版没有内置模型，查不了新查询的向量；把向量留作「同库相似 / 未来接 embedder」的材料，而不是当前召回的主路径。

### MEM5 · 写入路径

- agent 工具 `memory_remember` 与 `POST /api/memory/<persona>/facts` 都走同一条追加路径。
- 归档 / 修正不删行：追加 `revisions.jsonl` 一行，并追加一条同 id、`status=archived` 的新行；读时以「该 id 最后一行」为准。
- 追加写用 `storage.AtomicWriteFile` 不适用（追加语义），改为带 `O_APPEND` 的追加 + 0600；整库重写只在 compact 时发生（后置）。

### MEM6 · 隐私与可见性

- `visibility` 原值迁移，不升降级；列表与召回默认只回 `privileged`。
- `owner_principal` 原样保留，但接口输出掩码（只留首尾字符）；正文只在显式请求单条时返回完整。
- 工具调用日志只记「条数 + 耗时 + 查询长度」，不记查询正文与记忆正文（G6）。
- 迁移默认不迁 `providers[].api_key` / `accounts[].api_key`，改写为 `api_key_env` 引用（MG4）。

### MEM7 · 与 persona.json 的关系

`persona.json`（本机身份：名称、简介、头像、系统提示词，由 `internal/persona` 管理）**不等于** `memory/<persona>`（长期记忆库）。两者不合并语义：身份是展示与提示词，记忆是数据。UI 里「人格」与「记忆」是两个页签。

### MEM8 · 迁移是一次性插件，不是内置命令

迁移器按 `15-一次性插件.md` 的 NX1–NX7 交付：`mode=oneshot` + `run` 动作，用 `gqy run <path> --args '{...}'` 执行，跑完即清理。常驻二进制里不放迁移代码——数据转换只做一次，不该常驻。

### MG1 · 只读源

旧库一律 `file:<path>?mode=ro` 打开；备份目录只读遍历；任何情况下不写源。

### MG2 · 默认 dry-run

不带 `--apply` 只产报告：每个 unit 的条数、预估字节、跳过原因、警告。写目标必须显式 `--apply`。

### MG3 · 幂等与可重跑

- 新记录带 `legacy_id`（`<unit>:<表>:<主键>`）。
- `meta.json` 记 `migrated_from.source_fingerprint`（manifest 各 unit blake3 的聚合哈希）。
- 重跑按 `legacy_id` 做差集：只补新行，不重复、不覆盖用户改过的行。
- `episodes.source_key` 与 `facts.content` 的 sha256 作为第二层去重键。

### MG4 · 默认脱敏

旧配置 `secrets_included: true`，`providers[].api_key`、账号 token 一律不迁。默认写 `api_key_env`（如 `GQY_OPENAI_KEY`）并报告「已脱敏 N 项」；`--include-secrets` 才迁明文，目标文件 0600，报告里仍然不出现明文。

### MG5 · 可回滚

`--apply` 前把目标里将被覆盖的路径备份到 `$GQY_HOME/.migrate-backup/<timestamp>/`（`--no-backup` 关闭）。迁移只写自己管辖的路径：`memory/`、`personas.json`、根级配置文件、`kb/`、`prompts/`、`memes/`、`skills/`、`scripts/`、`identities/`、`.migrate-reports/`。

### MG6 · 单元独立

按 unit 迁移，单个 unit 失败不阻断其余；`--kinds` 选择本次要迁的单元；退出码：0 = 全部成功，1 = 部分失败，2 = 全部失败。

### MG7 · 大媒体默认不迁

`conversation.db`（约 195 MB）、`pictures/`（约 176 MB）、`documents/`、`ledger/`、平台消息历史属 archive 类：默认只报体积，`--kinds archive` 才复制。

### MG8 · 证据可追溯

每次运行写 `$GQY_HOME/.migrate-reports/<run-id>.json`：unit 计数、跳过原因、耗时、退出码、脱敏项数；**不含正文与密钥**。报告文件名带时间戳，可对比两次迁移的差异。

## 验收

1. 迁移真实备份到临时 `$GQY_HOME`：`facts=347`、`episodes=2054`、`revisions=47`、`evicted=0`；向量不完整要如实报告——embeddings 3031 条里能挂上 2085，孤儿 946（余量 630 + 挂不上记录 316）、缺向量 316、evicted 孤儿 192、合计 1138；manifest 声明 4 个 persona 库但磁盘只有 `default`，另外 3 个记 `missing`，不造空库。
2. `gqy-server` 起服务后 `GET /api/memory` 返回人格清单与统计；`POST /api/memory/default/recall` 同参数两次结果完全一致。
3. 重复执行 `--apply` 不新增记录（差集为空）。
4. 迁移报告与日志中没有明文密钥；`providers[].api_key`、QQ / iMessage token、voice minimax key、mcp env 里的 cookie 全部变成 env 引用。
5. `make check` 全绿；`gqy run <迁移器>` 跑完 `tmp/oneshot/` 无残留（默认清理）。

# 14 · 目标与支线

依据：`00-设计理念.md` 的 G7（可观测）；`01-架构.md` 的 agent 层职责（组装请求、工具调用编排、ask_user）；`05-会话与产物.md` 的 S1（会话是运行单元）、S2（事件流投影）；`06-工具.md` 的 T7（ask_user）。治理背景：`../reviews/2026-11-02-指令路由与真实性.md` 里「主线不被新指令打断、指令归因可溯源」的诉求。

## 范围

**做：**

- goal 模型：挂在会话上的长期目标，有 id、状态、最大轮数。
- 主线与支线：goal 运行中新指令不打断主线，进支线排队或独立支线会话。
- 支线两种形态与边界：同会话排队消息 vs 分叉会话。
- 支线完成后回报与合并；支线不覆盖主线上下文。
- 中断与恢复：goal 可 pause / resume；恢复时从事件流投影重建。
- 与 ask_user 的关系：主线暂停等答案时，其他消息进支线。

**不做（后置）：**

- 多 goal 并行、goal 之间的依赖与编排（DAG）。
- 自动 resume 调度、定时触发、智能抢占优先级：先只做「不打断」。
- 支线的权限与配额隔离：单机单用户，安全边界沿用 11 的信任模型。
- goal 的跨会话迁移与落盘细节：具体形状留给 blueprint/session 与对应施工单。
- 智能判断新指令是否紧急：默认全部进支线，不做自动升级。

## 决定

### GL1 · goal 定义与状态机

- goal 挂在会话上，是 agent loop 的长期上下文锚点。
- 字段：`id`、`title`（一句话）、`state`、`max_rounds`（最大轮数）、`created_at`。
- `state` 四值：`active` / `paused` / `completed` / `blocked`。
- 状态机：`active ⇄ paused`；`active → completed`（达成）或 `active → blocked`（轮数用尽 / 依赖缺失）；`paused` / `blocked` 可重新 `active`。
- `max_rounds` 是主线 loop 的轮数上限；用尽 → `blocked`，并报告未完成原因。

### GL2 · 主线优先：新指令不打断主线

- goal 处于 `active` 且 loop 运行中时，用户新来的其他指令不打断主线。
- 新指令走支线：同会话排队，或作为独立支线会话并行。
- 主线继续推进当前轮；支线完成后回报并合并（GL4）。

### GL3 · 支线两种形态与边界

| 形态 | 适用 | 语义 |
| --- | --- | --- |
| 同会话排队消息 | 轻量、只影响主线下一步 | 先记下，当前轮结束后处理；不自动进主线上下文 |
| 分叉会话 | 独立任务、需要自己的上下文与工具轨迹 | 新建会话，复用 05 S1 的会话单元与 S2 的事件流投影；标记父会话 id 与合并关系 |

- 边界判据：新指令只需要主线「之后做某事」→ 排队消息；需要独立上下文、长任务或独立工具轨迹 → 分叉会话。
- 分叉会话的会话树（父会话 id、分支关系）由本文新定；落盘形状留给 blueprint/session 后续补齐。

### GL4 · 支线回报与合并

- 支线完成后回报：结果写支线自己的事件流，并向主线或用户提交一句话摘要。
- 合并进主线：只有主线显式采纳（用户确认或 agent 决定）时，才把支线结果写进主线上下文。
- 不自动合并：支线不覆盖主线上下文，避免污染主线的事实与工具轨迹。

### GL5 · 中断与恢复

- goal 可 `pause` / `resume`：pause 冻结主线 loop，支线可继续。
- 支线不覆盖主线上下文：支线的消息与工具轨迹写进支线自己的事件流。
- resume 时从主线事件流投影重建上下文（05 S2），继续最后一轮；事件流是真相源，不另存上下文副本。

### GL6 · 与 ask_user 的关系

- 主线遇到 ask_user（06 T7）→ 暂停等答案，loop 挂起在 `question`。
- 答案通过 question 回填通道（数字键 / 自定义答案）进入主线；用户此时发来的其他消息默认进支线，不污染主线上下文。
- 用户取消或超时未答 → 主线保持暂停，goal 状态不变，用户可 resume 或改 goal。

## 数据样例

goal 记录：

```json
{"id": "goal-001", "title": "把插件文档补齐", "state": "active", "max_rounds": 20, "created_at": "2026-11-02T19:00:00+08:00"}
```

## 验收

1. active 主线运行中发新消息：主线继续，新消息进排队或分叉，主线上下文不含新指令。
2. 排队消息在当前轮结束后被处理；分叉会话独立记录事件流，合并只经显式采纳。
3. pause 后主线 loop 冻结；resume 从事件流重建到最后一轮并继续。
4. ask_user 挂起时：答案回填主线，其他消息进支线；取消后主线保持暂停。
5. `max_rounds` 用尽 → goal `blocked`，并报告未完成原因。
6. goal 状态与支线关系可观测（G7）：状态接口或会话列表可见。

# 16 · 并发与多租户

日期：2026-11-02
状态：已定（2026-11-02，实现落地）

## 问题

一个任务（绘画、编码、调研……）可能同时开很多 agent / 团队；网关要能扛住高并发、开销低，并且**任务之间互不干扰**。另外，非 GQY 的 agent 也会接进来——它们需要一个统一入口，把协议、错误、配额、日志都规范掉。

## 决定

### MT1 · 三层并发控制
请求进网关依次经过：**租户池 → 账号池 → 上游连接**。租户池保证任务间隔离，账号池对应上游并发上限，两者都满才排队；排队有 `queue_timeout_ms` 上限，超时返回 `tenant_queue_timeout`（租户池）或 `queue_timeout`（账号池）。

### MT2 · 租户标识
租户 = 任务 / 工作区 / agent。请求头 `X-GQY-Tenant`（别名 `X-GQY-Task`）标识；缺省 `default`。名字限定 `[A-Za-z0-9_.-]{1,64}`，非法直接 400 `invalid_tenant`。

### MT3 · 隔离与配额
- **独立并发池**：每个租户 `max_concurrency` 个槽，打满只排队自己。
- **每分钟配额**：`req_per_min`，超限 429 `tenant_quota` + `Retry-After`。
- **未登记租户**：一旦 `routing.json` 里配置了 `tenants`，未登记的名字一律 400 `tenant_unknown`，防止绕过配额。
- **独立错误域**：租户的拒绝/超时只影响自己的请求，不改变其他租户的候选与冷却状态。

### MT4 · 公平
同一租户内按到达顺序排队（FIFO）；租户之间不做抢占式借调——简单、可预测、开销低。需要「小任务快、大任务不饿死」时，用不同租户分别配额即可。

### MT5 · 低开销
- 请求日志**异步批量写**：有界队列（4096）+ 批量落盘（512 条或 100ms），队列满丢弃并计数（`Dropped()`），日志永不阻塞请求路径。
- 租户状态是常数开销：一个信号量 + 一个固定窗口计数，都在短临界区内。
- 网关不做跨请求的大对象复制；候选解析与亲和查找保持 O(候选数)。

### MT6 · 跨 agent 规范层
任何 agent（Claude Code、Codex、自研脚本……）把 `base_url` 指向 GQY 的 `/v1`、`/v1/messages` 或 `/v1beta`，就获得：三种协议统一翻译、统一错误码、失败转移与冷却、租户配额、请求日志、密钥治理。接入方式见 [`reference/agent-onboarding.md`](../reference/agent-onboarding.md)。

### MT7 · 配置
`routing.json` 增加 `tenants`：

```json
{
  "tenants": [
    {"name": "drawing", "max_concurrency": 8, "req_per_min": 600},
    {"name": "coding",  "max_concurrency": 4, "req_per_min": 300}
  ]
}
```

`max_concurrency` 0 表示不单独限制（仍受账号池约束）；`req_per_min` 0 表示不限。

### MT8 · 可观测
`GET /api/gateway/status` 返回每个租户的 `in_flight / peak / queued / accepted / rejected / req_per_min / max_concurrency`；`requests.jsonl` 每行带 `tenant` 字段。

## 落点

```
app/internal/config/{types,load}.go       # tenants 配置与校验
app/internal/gateway/tenant.go            # 租户池、配额、观测
app/internal/gateway/logwriter.go         # 异步批量日志（MT5）
app/internal/gateway/router.go            # 三层顺序接入 + 日志带 tenant
app/internal/httpapi/middleware.go        # X-GQY-Tenant 解析与校验
app/internal/httpapi/handlers.go          # status 返回租户快照
```

## 不做（后置）

- 跨租户抢占式借调与加权公平队列（MT4 保持 FIFO + 独立配额）。
- 租户级独立鉴权密钥（当前共享 `GQY_AUTH_TOKEN`，租户名可伪造——见「风险」）。
- 租户级模型白名单与预算（每日 token 上限已在账号维度）。

## 风险

- 租户名来自请求头，**不是鉴权凭据**：能访问网关的人可以冒充别的租户。真正的隔离边界是「谁能连上网关」；需要更强隔离时给每个 agent 发独立 token，再把 token 映射到租户（后置）。
- 队列满丢弃日志会丢可观测性，需监控 `Dropped()`。

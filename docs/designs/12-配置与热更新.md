# 12 · 配置与热更新

依据：`00-设计理念.md` 的 G1（本地优先）、G2（多供应商、可替换）、G6（安全与配额兜底）、G7（可观测）；`01-架构.md` 的 D1（Go）、D4（`gqy-server` 承载配置与存储）；`02-网关与路由.md` 的 R1–R8（providers.json / routing.json 字段与校验规则）。调研依据：`../reviews/2026-11-02-配置热更新-调研.md`。

## 范围

**做：**

- 配置清单：`providers.json`、`routing.json`、`settings.json`、环境变量，各自管什么、谁热更新谁重启。
- 热更新模型：文件监视（fsnotify）→ 解析 → 校验 → 整体原子切换；新请求用新快照、在途请求用旧快照。
- 失败处理：校验失败保留旧配置，错误落日志、进状态接口。
- 手动重载：`POST /api/config/reload`，可选 SIGHUP；同步返回结果。
- 密钥只写不读：热更新不改变这条边界（延续 R5）。

**不做（后置）：**

- 插件装卸与插件配置的热更新：归 `04-插件运行时.md`，本文不写。
- 逐字段增量配置 CRUD：只做整份声明式替换，避免中间态。
- 配置中心 / 控制面下发（xDS、etcd、数据库）：单机单用户，文件就是控制面。
- 配置版本回滚（多版本保留、一键回退）：失败即保留旧配置，不额外存历史版本。
- 远程修改本机配置：重载端点只在本机鉴权范围内。

## 决定

### CF1 · 运行时只有一份不可变快照

`providers.json`、`routing.json`、`settings.json` 与启动环境变量共同构成配置事实。进程启动时把它们解析成一份不可变快照；运行时全部读快照，不直接读文件。重载就是「造新快照，整份换指针」。

**为什么**：并发读写半份配置是重载事故的主要来源；整份不可变快照让「校验后再生效」「在途请求用旧配置」都变成指针换引用的自然语义，而不是到处加锁。

### CF2 · 文件与环境变量分工

- 常改的运行数据放文件：`providers.json`、`routing.json`、`settings.json`，随文件热更新。
- 进程身份与安全边界放环境变量：`GQY_HOME`、`HOST`/`PORT`、`GQY_AUTH_TOKEN`、`GQY_WORKSPACE`、`GQY_TOOL_ROOTS`、`GQY_MOCK`，只在启动时读一次，改动需重启。
- 密钥按 R5：文件里 `api_key` 可写、可热更新；环境变量 `GQY_PROVIDER_<ID>_API_KEY` 启动时读一次，改动需重启。

**为什么**：环境变量决定进程怎么起（监听、数据根、鉴权、工具边界），中途改动副作用大且难以被用户感知；文件是用户日常编辑的对象，热更新收益最大。职责分开了，才不会出现「改了 env 以为生效」的错觉。

### CF3 · 热更新范围

| 配置 | 位置 | 生效方式 |
| --- | --- | --- |
| providers（provider/账号/模型/并发/配额） | `$GQY_HOME/providers.json` | 热更新 |
| routing（default/groups/策略/上限） | `$GQY_HOME/routing.json` | 热更新 |
| settings（运行设置，见下） | `$GQY_HOME/settings.json` | 热更新 |
| 监听地址、数据根、鉴权令牌、工具根、mock 开关 | 环境变量 / `.env` | 重启生效 |
| 环境变量 provider 密钥 `GQY_PROVIDER_<ID>_API_KEY` | 环境变量 | 重启生效 |

**为什么**：把「改了就能生效」和「改了要重启」显式列出来，避免用户试错；也划定本文边界——凡是环境变量承载的，不在热更新机制里做特殊处理。

### CF4 · 重载管线：读 → 解析 → 校验 → 整体切换

文件监视触发与手动触发走同一条管线：

1. 整读文件（一次读全，不允许读到半写内容）。
2. JSON 解析。
3. 结构校验：复用 `02-网关与路由.md` 的规则——providers `id` 唯一、`protocol` 白名单；routing `groups[].id` 唯一、`strategy` 只认 order/rotate/usage、`max_attempts` ≤ 5、`cooldown_seconds` ≤ 600、`members` 可解析；settings 字段类型与上限。
4. 构造新快照，原子切换（CF5）。

任何一步失败：保留旧快照，错误落日志、写进状态接口，不半新半旧。

**为什么**：Nginx「先查语法、失败回滚」、Kong「parse 再 load」、Prometheus「坏配置不生效」是三方共识；GQY 把校验放在切换之前，换来的是「重载永远不会把服务打挂」。

### CF5 · 原子切换：新请求用新快照，在途请求用旧快照

切换只改一个原子指针。每个请求在入口处取一次快照并贯穿到底；已经开始处理、尤其已开始流式输出的请求，继续用旧快照完成，不被打断。

**为什么**：等价于 nginx「旧 worker 服务老客户端」、Envoy「drain 期间旧进程把已有连接服务完」。单进程里用快照实现，成本是一个指针，不需要第二进程，也不迁移连接。

### CF6 · 文件监视：目录级 fsnotify + 事件合并

监视 `$GQY_HOME` 配置目录，不监视单个文件；按文件名过滤出 `providers.json` / `routing.json` / `settings.json`，写事件与 rename 事件都触发重载。连续事件合并（约 200ms 静默窗口），一批改动只重载一次。目录监视失败（如目录被删）时报错落日志，退化为只靠手动重载。

**为什么**：fsnotify 官方明确建议监视父目录——编辑器原子保存会「写临时文件再 rename」，只盯文件会丢 watch；合并事件防止一次保存触发多次、甚至读到半写文件。Kubernetes controller 的水平触发给了同一个直觉：漏了事件不要紧，下一次重读会补齐。

### CF7 · 手动重载端点与信号

- `POST /api/config/reload`：走 `/api` 鉴权（`GQY_AUTH_TOKEN`），同步执行一次重载管线；成功返回 `200` + 新配置版本号，失败返回 `400` / `422` + 错误明细（不含密钥）。
- 收到 SIGHUP 同样触发一次重载（Prometheus 先例）。
- 文件监视默认开启，可在 `settings.json` 关闭（批量改文件时防抖）。

**为什么**：给脚本、测试、以及「监视意外失效」的场景兜底；同步返回让调用方立刻知道成没成，不用猜。

### CF8 · 密钥只写不读，重载不泄漏

快照里存明文密钥仅供出站请求使用。任何读接口（`/api/gateway/status`、`/api/config/reload` 的返回、未来配置查看端点）只返回 `api_key_set`，不返回明文；重载错误与日志不打印 `api_key` 值。延续 R5。

**为什么**：G6「密钥只写不读；日志不落正文」；热更新会反复经过密钥字段，必须保证这条边界不因重载而变松。

### CF9 · 缺失文件与默认值

`providers.json` / `routing.json` 缺失或为空时，启动用内置默认：routing 默认值与 `02-网关与路由.md` 样本一致，providers 回退环境变量 provider。文件首次出现后，监视自动接管并热更新。`settings.json` 缺失用全默认。

**为什么**：第一次运行不该因为没有文件就起不来；文件出现即升级为「文件驱动」，与 G1「谁用谁付」一致。

### CF10 · 依赖与归属

`fsnotify` 是唯一新增外部依赖（Go 标准库没有文件监视），锁在 `config` 包的文件监视部分，不进入 `gateway` / `session` / `agent` 热路径。快照类型与校验函数放 `config` 包，启动与重载共用同一套。插件装卸与插件配置的热更新不在此文，见 `04-插件运行时.md`。

**为什么**：D1「标准库优先、少依赖」——fsnotify 是 Go 生态事实标准、单一小依赖，换来监视、rename 与半写防护；把配置机制收口在一个包，校验只写一份。

## 数据

### 配置清单

| 文件 / 来源 | 管什么 | 字段依据 |
| --- | --- | --- |
| `providers.json` | 多 provider 多账号：id、base_url、protocol、models、accounts、max_concurrency | `02-网关与路由.md` |
| `routing.json` | 默认模型、路由组、策略、max_attempts、cooldown_seconds、queue_timeout_ms | `02-网关与路由.md` |
| `settings.json` | 运行设置：限流、工具超时、shell 白名单等可热更参数 | 本文新定，字段随主题文档扩展 |
| 环境变量 / `.env` | 启动参数与密钥兜底 | 旧实现 `app/internal/config/config.go` + 本文 CF2 |

### settings.json（样本）

```json
{
  "watch_enabled": true,
  "rate_limit": 0,
  "tool_timeout_s": 120,
  "shell_timeout_s": 60,
  "shell_allowlist": []
}
```

只定机制不定全量字段：工具类字段由 `06-工具.md` 扩展，前端设置页由 `10-前端界面.md` 定 UI，本文只保证「settings.json 参与快照、可热更新、失败回滚」。

## 验收（本设计对应的最小闭环）

1. 改 `routing.json` 合法内容（如换策略）→ 不重启，新请求走新策略。
2. 写入非法 JSON、重复 `groups[].id`、`max_attempts` 超上限 → 旧配置继续服务，日志有错误，状态接口显示最近一次重载失败。
3. 用编辑器原子保存、连续多次保存 → 只重载一次，且不会读到半文件。
4. 流式已开始的请求进行中改配置 → 该请求仍按旧快照完成，响应头 `X-GQY-Provider` 一致。
5. `POST /api/config/reload` 成功返回版本号、失败返回错误明细；未带鉴权被拒绝。
6. 状态接口与配置查看只看到 `api_key_set`，看不到明文密钥。

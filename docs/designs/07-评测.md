# 07 · 评测

依据：`00-设计理念.md` 的 G5（评测驱动）；`01-架构.md` 的 D1（Go）、D4（`gqy-eval` 子命令、eval 不占服务额度）；`02-网关与路由.md` 的 R1–R8（复用 gateway 路由与转移）；`03-协议翻译.md` 的 C9（错误归一可复用）。

## 范围

**做：**

- 三维实验矩阵：prompt / schema / return；单因素 / 两两 / 全组合三阶段；用例组合与筛选。
- 单次对话循环：渲染 → 请求 → 工具执行 → 回填；规则判定为主、模型裁判补充。
- 结果落盘（recorder）、回放（replay）、报告（report）；失败可复现。
- 命令行入口 `gqy-eval`；评测复用 gateway / tool / plugin，不进常驻服务。
- 契约测试与评测的分工。

**不做（后置）：**

- 模型裁判做主判定：规则判定仍是主判定，模型结果单独记录、标注来源。
- 跨轮自动比较、自动写回线上配置。
- 并行压测与大规模并发：先小并发、组内串行。
- 评测服务化 / HTTP API：只做 CLI 一次性任务（D4）。
- 评测结果回灌网关路由策略：那是配置数据问题，不在本设计。

## 决定

### E1 · 评测是独立 CLI，不进常驻服务

- `gqy-eval` 是一次性子命令：跑完即退，不占 `gqy-server` 的并发额度（01 D4、G1）。
- 复用 `gateway` / `tool` / `plugin` 包；不启动 HTTP 服务，不写会话。
- 评测输出目录由 `-out` 指定，与 `$GQY_HOME` 运行态分开。

### E2 · 三维实验矩阵与筛选

三个维度，取值显式枚举在配置里，不写代码：

| 维度 | 变体（代号） |
| --- | --- |
| prompt | none / basic / when / when-how / fewshot / strict |
| schema | min / full / example / negative / alias |
| return | raw / trim / summary / typed / error-rich / error-min |

组合分三阶段，每轮打 `round` / `axis` 标签：

| stage | 做法 |
| --- | --- |
| single | 固定两维，扫第三维；找每个维度值得留的变体 |
| pair | 阶段胜出变体两两组合；验证交互效应 |
| full | 胜出组合全组合，每组 N≥5 看稳定性 |

筛选与增量：

- `-filter prompt=basic` 按维度取值筛选；`-dry-run` 只打印矩阵与用例数，不发请求。
- 增量模式只跑变化的维度组合。
- 温度固定低值（0 或接近 0）；稳定性靠重复次数，不靠高温采样。

### E3 · 用例集：输入 + 期望行为

`cases.json` 的每个用例是「输入 + 期望行为」，不做逐字相等：

```json
{
  "version": "1",
  "cases": [
    {
      "id": "echo-basic",
      "input": "把我说的这句话原样回显：hello",
      "expect": {
        "should_call": true,
        "tool": "echo__echo",
        "arg_contains": {"text": "hello"},
        "final_contains": ["hello"],
        "must_not_call": false
      },
      "inject": null
    }
  ]
}
```

- 用例覆盖调用决策空间：必调用 / 不该调用 / 参数歧义 / 边界值 / 工具返回异常 / 多工具选择 / 多轮依赖。
- `inject` 是故障注入对象：`empty` / `error` / `timeout` / `slow`，由评测宿主执行。
- 用例集与判定器带版本号，一轮内冻结；新增用例进下一轮。

### E4 · 单次对话循环

固定流程：

1. 按配置渲染 system / user / tools schema。
2. 发模型请求，走统一内部模型（03 C1/C2）与 gateway（02 R1–R8）。
3. 响应含 tool_call：校验参数（记录，可选拦截）→ 走 tool / plugin 统一入口执行 → 按 return 变体渲染回填 → 回第 2 步。
4. 响应是最终答案：结束，进判定。
5. 超时或超过 `max_rounds`：标记 `not_converged`，仍进判定。

- 每步的请求 / 响应 / 工具调用 / 返回值全量录制。
- 工具执行失败记 `exec_error`；模型侧失败记 `gateway_error`；两者不混进模型决策错误。

### E5 · 判定：规则优先，模型裁判补充

规则判定（主判定）：

- `should_call`：断言至少一次 / 零次工具调用。
- `tool`：调用名匹配。
- `arg_contains`：参数 JSON 包含指定子串 / 值。
- `final_contains`：最终答案包含全部关键事实。
- `must_not_call`：禁止调用某工具。

模型裁判（补充）：

- 只用于主观项；裁判模型固定、温度 0、判定模板固定。
- 结果单独记录并标注来源，不与规则判定合并。

状态分类（复用 03 C9 的错误归一）：

| status | 含义 |
| --- | --- |
| ok | 判定通过 |
| not_converged | 超轮次 / 超时，未收敛 |
| gateway_error | 模型侧失败：连接 / 5xx / 429 耗尽等 |
| exec_error | 工具 / 插件执行失败 |

- 人工抽检：每配置随机 5% 复核，校准判定器。

### E6 · 落盘：全量录制、带版本

目录（`-out` 指定，建议 `docs/test_call_<tool>/`）：

```
<out>/
  configs/{round}-{ts}.json
  runs/{round}-{ts}/
    runs.jsonl
    trace/{run_id}.json
    cases/cases.json
    errors.log
  report/{round}-{ts}.md
  best/current.json
```

`runs.jsonl` 每行一条：

```json
{
  "run_id": "…", "case_id": "echo-basic", "repeat_idx": 0,
  "round": "single", "axis": "return",
  "config": {"prompt": "basic", "schema": "full", "return": "raw", "model": "…", "gateway_ver": "…", "judge_ver": "…"},
  "messages_masked": ["…"],
  "tool_calls": [{"name": "…", "args_raw": "…", "schema_valid": true, "exec_ok": true, "ret_rendered": "…", "latency_ms": 12}],
  "final_answer": "…", "rounds_used": 1, "tokens": {"in": 10, "out": 8}, "total_ms": 120,
  "judge": {"rule": {"pass": true, "reasons": []}, "model": null},
  "status": "ok"
}
```

- 每轮记录版本：模型、网关、用例集、判定器、插件、适配器、插件协议。
- 落盘前对 `api_key/token/secret/authorization` 等脱敏（G6）。
- 禁止跨轮比较；`best/current.json` 只由完整轮次胜出结果写入。

### E7 · 回放：从 trace 不发真实请求

- `-replay <trace 目录>` 用录制的模型响应重放，不发真实模型请求。
- 回放同样产出 runs.jsonl 与报告，标记 `replay: true`。
- 用途：验证判定器、渲染逻辑改动是否影响既有结果；失败可复现。

### E8 · 报告与指标

`report.md` 固定包含：

1. 配置快照摘要（三维度、模型、用例数、重复数）。
2. 矩阵汇总表：行 = 组合，列 = 指标，按端到端成功率排序。
3. 单因素对比：每个维度内变体对比，标显著差异。
4. 交互效应说明：两两组合是否出现非加性变化。
5. 反例清单：失败最多的 10 个用例 + trace 链接。
6. 结论与建议：胜出配置、为什么、适用边界。
7. 成本：总 token、总耗时、单次平均成本。

指标（每配置 × 每用例聚合）：调用决策准确率、工具选择准确率、参数合规率、返回值利用率、端到端成功率、平均轮次 / token / 延迟、稳定性（同配置 N 次一致率）。

### E9 · 契约测试与评测的分工

| 维度 | 契约测试 | 评测 |
| --- | --- | --- |
| 管什么 | 链路正确：调用、协议、状态机 | 能力正确：模型决策、prompt / schema / return 效果 |
| 例子 | 插件加载 / 调用 / 关闭 / 重复 id / 超时 / 进程退出；协议往返字段映射（03 验收）；网关解析 / 转移（02 验收） | 「该调是否调、调哪个、参数对不对、最终答案含关键事实」 |
| 上游 | 假上游 / 假插件，确定性强 | 真实模型 + 真实工具（或注入故障） |
| 时机 | 进 CI，每次跑 | 按轮次跑；胜出配置固化后进回归 |

- 两者共享同一套 tool / plugin 运行时与统一内部模型；契约测试断言「没坏」，评测断言「够好」。

### E10 · 成本与并发控制

- 矩阵执行按配置分组小并发，组内串行；不做大并发压测。
- 对 provider 限流退避重试；重试落盘并标 `retry_of`，不悄悄吞。
- 插件 / 工具执行设超时，超时视为失败样本，不重试（重试会污染稳定性指标）。
- 成本控制：single / pair 小样本快筛，full 才放大；支持增量只跑变化维度。

## 验收

1. 单因素矩阵：固定两维扫第三维，配置快照与 runs.jsonl 的 round / axis 标签正确。
2. 一次「请求 → 工具执行 → 回填 → 最终答案」全链路跑通，runs.jsonl / trace / report / cases 快照齐全。
3. 规则判定五条规则各有一个通过用例与一个反例。
4. `-replay` 从 trace 回放不发真实请求，产出判定与原轮一致。
5. `-dry-run` 只打印矩阵与用例数，不发请求。
6. 故障注入 empty / error / timeout / slow 各产出对应 status 样本。
7. 脱敏：runs.jsonl 与 trace 无 api_key / token / secret 明文。

# 17 · 插件规范与双模式

日期：2026-11-02
状态：已定（2026-11-02，实现落地）

## 问题

插件要进 WebUI：每个插件要有**设置按钮、可配置项、删除**。同时插件有两种来源——**在线安装**（上线模式，不能改本体）与 **GQY 自主创建**（开发模式，本地使用、随时可改）。规矩必须能被机器强制，否则仓库一多就会漂。

## 决定

### PL1 · 一份 manifest 规范
`docs/reference/plugin-manifest.md` 是唯一规范：字段、两种模式、设置 schema、生命周期、强制校验。插件仓库不许自造字段语义。

### PL2 · 两种模式由「安装标记」判定
- 目录含 `.gqy-installed`（或 manifest 声明 `"source":"installed"`）→ **installed / 只读**；
- 否则 → **local / 可改**（开发模式）。
- 判定在扫描时派生，写入 `PluginStatus.source` / `read_only`，WebUI 显示「已安装 / 本地自建」徽标。

### PL3 · 设置与本体分离
- 插件在 manifest 里声明 `settings` schema（string/number/boolean/select）。
- 用户设置值存 `$GQY_HOME/plugin-settings/<id>.json`（0600），**永不写进插件目录**——所以安装版也能配置而不破坏只读语义。
- API：`GET|PUT /api/plugins/{id}/settings`；保存时按 schema 严格校验（未知键/类型/选项越界拒绝；`null` 恢复默认）。
- 生效值 = 默认值 + 已保存值，接口返回 `schema/values/effective/source/read_only`。

### PL4 · 删除是「卸载 + 移除」
`DELETE /api/plugins/{id}`：已加载则先卸载，再删插件目录与设置文件；目录必须位于 `plugins/` 内（路径穿越拒绝）。两种模式都可删，区别只在「本体能不能改」。

### PL5 · WebUI 契约
插件页每个插件必须有三类操作：**设置**（有 schema 时显示）、**加载/卸载**、**删除**（二次确认，文案说明会删目录与设置）。模式徽标解释「只读/可改」。

### PL6 · 能强制的就强制
- `TestPluginReposConform` 校验 GQY 内置插件与同级 `gqy-plugins-*` 仓库的 manifest（id/name/version/protocol/command/actions/settings 类型、源码仓库不得带安装标记）。
- 不合规 → 测试失败 → `make check` 失败；CI 上等于无法合并。

### PL7 · 不能强制的就发现并通告
- 「别人在本地随便改插件」无法用代码禁止（文件系统权限之外），只能靠安装标记 + 只读语义 + 文档。
- 新规范写进 org `STANDARDS.md` 与各仓库可读的 `docs/reference/plugin-manifest.md`；正在改仓库的 agent 只要读文档就会看到。

### PL8 · 安装器边界（后置）
安装器（`gqy-plugin` CLI）负责下载、sha256 校验、解包、写标记；本轮只定义标记与只读语义，安装器实现仍属 `gqy-plugins` 仓库路线图。

## 落点

```
app/internal/plugin/{plugin.go, settings.go, settings_test.go, repos_test.go}
app/internal/httpapi/{plugins.go, server.go}
app/js/{api.js, settings.js, store.js}
app/styles/app.css
docs/reference/plugin-manifest.md
```

## 不做

- 插件本体在线编辑（开发模式也只改文件，不走 WebUI 编辑器）。
- 安装器与在线目录条目（`gqy-plugins` 仓库路线图）。
- 设置项加密存储（当前明文 0600，敏感设置交由外部密钥管理）。

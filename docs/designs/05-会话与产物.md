# 05 · 会话与产物

依据：`00-设计理念.md` 的 G1（本地优先）、G6（安全与配额兜底）；`01-架构.md` 的 D4（`gqy-server` / `gqy-clean` 分工）；`02-网关与路由.md` 的 R4（会话亲和键 = 会话 id）。

## 术语与边界

- **会话 Session**：一次对话/任务的运行单元，记为 `$SESSION_ID`；同时是网关亲和（R4）的键。
- **消息 Message**：会话里的最小内容单元（user / assistant / tool）。
- **产物 Artifact**：任务完成后需要交付或保留的文件，分最终产物和中间产物。
- **运行态文件 Runtime Files**：临时文件、工具日志、上下文快照等，不等同于交付产物。
- **工作区 Workspace**：用户选定的项目根目录，记为 `$WORKSPACE`。
- **数据根**：`$GQY_HOME`，默认 `~/.gqy`，所有会话级数据在其下。

## 范围

**做：**

- 会话创建、切换、草稿、重试、停止。
- 流式回复的事件模型：thinking / tool / text / question / emote / done（六种，见 S2 与 S8）。
- 消息里的思考过程与工具轨迹。
- 产物：附件上传（文本注入、图片多模态、其他二进制落盘）、产物灯箱。
- `ask_user` 提问卡片。
- 目录规范与生命周期清理（`gqy-clean`）。

**不做（后置）：**

- 多用户、会话分享、云端同步。
- 向量检索的知识库（当前是关键词匹配，见 `19-知识库.md` 主题）。
- 会话级权限系统（在 `11-安全与沙盒.md` 只做工具边界）。

## 决定

### S1 · 会话是一次对话的运行单元

- 每个会话一个 `$SESSION_ID`；创建时落 `manifest.json`，记录会话 id、工作区、创建时间、产物索引、清理策略。
- 会话 id 同时是网关会话亲和的键（R4）：同会话固定 provider/账号。
- 会话列表本地索引，不依赖在线服务。

### S2 · 流式事件模型

一次回复的 SSE 事件只有六种，前端只认这六种：

| 事件 | 含义 |
| --- | --- |
| `thinking` | 思考过程，可折叠 |
| `tool` | 一次工具调用的开始/参数/输出/耗时/状态 |
| `text` | 正文增量 |
| `question` | `ask_user` 提问：选项 / 数字键 / 自定义答案 |
| `emote` | 回复末尾的自动表情（S8）：名称 / 标签 / 文件 / 分数 / none 分数；没发就是没有这条事件 |
| `done` | 回复结束，带用量与停止原因 |

- 事件是追加的投影：任何界面都能从事件流重建出消息；`emote` 只是多一条可追加事件，旧的五事件流仍按原样解析、重建。
- 顺序固定：`emote` 在正文之后、`done` 之前。`done` 是收尾标记，`emote` 属于本轮回复的一部分。
- 前端把 `emote` 渲染在回复正文末尾、操作按钮之前，是一张表情图；图片不内联在事件里，前端按需调插件 `show`（`inline:true`）取 data URI，取不到就整块不渲染（静默）。
- 事件缺失不等于错误：插件未安装 / 未加载、设置关闭、模型判断不该发、调用失败或超时，都只是没有 `emote`，回复照常完整。
- 非流式请求返回同样的事件序列，只是不逐块推送。

### S3 · 产物与附件

- **附件上传**：文本注入上下文、图片走多模态、其他二进制落盘到会话目录；文件名用 O_EXCL 抢占，并发同名不覆盖。
- **产物灯箱**：消息关联的产物进入灯箱，支持文件面板、代码高亮、图片预览。
- **最终产物 vs 中间产物**：只有用户确认交付的才是最终产物；模型生成的临时文件放 `tmp/generated/`，不混进交付。

### S4 · 草稿、重试、停止

- 草稿按会话保存：切换会话不丢输入框内容。
- 停止 = 前端发停止信号，服务端取消在途请求（AbortController 语义），已产出的增量保留。
- 重试 = 以当前消息为界重新发起一轮，不覆盖历史；旧回复标记为被替代。

### S5 · 目录规范

```
$GQY_HOME/sessions/$SESSION_ID/
  manifest.json
  tmp/
    uploads/        # 用户上传或引用的临时文件
    generated/      # 模型生成、未确认交付的临时产物
    scratch/        # 可随时删除的中间文件
  logs/
    tools/2026-10-22.jsonl   # 每次工具调用一行
  io/
    input/
    output/
    context/        # context.md、messages.jsonl，便于调试
    webui/          # open.sh + index.html，只读可视化
  scripts/
```

工作区内的临时目录（agent 执行产生的临时代码、补丁草稿、可重建文件）：

```
$WORKSPACE/.gqy/tmp/
  code/
  patches/
```

要求：

- 工作区临时目录自动进 `.gitignore`，不污染项目版本库；任务成功后默认清理，失败可保留。
- 工作区不可写时，回退到 `$SESSION_DIR/tmp/workspace/`。
- 工具日志一行一条，字段至少：`timestamp`、`tool_name`、`status`、`duration_ms`、`input_summary`、`output_summary`、`artifact_paths`；敏感参数脱敏。

### S6 · 生命周期与清理

- 会话临时目录 `tmp/` 默认保留 7 天；工具日志与上下文快照默认保留 30 天；均可配置。
- 工作区临时代码：任务成功后默认清理；失败保留以便排查。
- 清理入口：`gqy-clean --session <id>`、`gqy-clean --expired`（按 TTL）。

### S7 · 安全

- 会话目录 0700，敏感文件 0600。
- 所有路径经 `$GQY_HOME` / `$SESSION_ID` / `$WORKSPACE` 解析并规范化，防 `../` 穿越。
- 日志与上下文明文脱敏：不记录密钥、token、完整环境变量。

### S8 · 回复后自动表情：核心触发，事件追加

**含义**：每轮回复正文结束（有正文、且本轮没有触发 `ask_user`）后，GQY 核心问一次表情包插件「该不该发、发哪张」；决定发就在 `done` 之前追加一条 `emote` 事件，并落进会话事件流。表情只出现在界面上，不进模型上下文。

**为什么由核心触发，而不是插件自驱**：

- 插件只有动作：运行时把 manifest 的 `actions` 注册成工具（04 P11），没有「回复完成」这类生命周期钩子，插件无从知道一轮对话什么时候结束。
- 即使给钩子，也要把正文、用户语境、SSE 连接一并交给插件，等于把会话编排外包。核心触发时插件只做一个纯函数式的 `suggest`（给语境、回候选 + none 分数），无状态、随时可卸载。
- 失败隔离简单：核心调用超时或报错就静默跳过，回复不受影响。

**触发条件**（全部满足才发）：

1. 插件 `emote-pack-default` 已发现、已加载、状态 `ready`；
2. 插件设置 `auto_emote` 为真（manifest 默认 `true`，只有显式 `false` 才关）；
3. 插件 `suggest` 判 `decision = emote`；
4. top1 分数 ≥ 插件设置 `min_score`（默认 0，范围 0–1）。

语境取本轮用户消息（空白视为无语境；超过 2000 字符取末尾，按插件契约上限）；调用 `suggest` 时 `limit = 3`、超时 3 秒，只取 top1。同一轮最多一条。任一条件不满足，或调用失败 / 超时 / 返回不可解析，一律静默跳过：不写事件、不改回复、不报错。

**关闭方式**（两档，都不用改代码）：

- 软关：插件设置页把 `auto_emote` 设为 false —— 插件与其它动作（list / show / match / suggest）照常可用，只是不再自动发表情。
- 硬关：卸载或删除插件 —— 核心找不到 ready 的插件，自然没有 `emote` 事件。

设置值存在 `$GQY_HOME/plugin-settings/<id>.json`，不写插件目录（PL3）；核心每次取「默认值 + 已保存值」的生效设置，改设置即时影响下一次回复。

**不做（后置）**：

- 不做多插件表情路由：固定只认 `emote-pack-default`，不按人格 / 场景切换表情包。
- 不做用户手动选表情，不把表情图回灌进模型上下文。
- 不给旧客户端做兼容层：未知事件类型按忽略处理，旧客户端只是看不到表情。

## 数据样例

`manifest.json`：

```json
{
  "session_id": "…",
  "workspace": "/path/to/project",
  "created_at": "…",
  "artifacts": [],
  "cleanup_policy": {"session_tmp_ttl_days": 7, "logs_ttl_days": 30}
}
```

## 验收

1. 六种 SSE 事件按序可重放成消息（`emote` 在 `done` 之前、可缺省）；非流式与流式内容一致。
2. 同名附件并发上传不互相覆盖。
3. 切会话草稿不丢；停止后已产出增量保留；重试不覆盖历史。
4. `gqy-clean --expired` 只清过期目录，不动未到期会话。
5. `../` 路径被拒绝；密钥/token 不出现在工具日志里。

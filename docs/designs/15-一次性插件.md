# 15 · 一次性插件

依据：`00-设计理念.md` 的 G1（谁用谁付）、G4（插件可扩展）；`04-插件运行时.md` 的 P3（manifest）、P5（生命周期）、P8（进程回收）、P9（热更新）、P11（工具注册）；`09-存储.md` 的 ST2（派生可重建）、ST7（清理）；`11-安全与沙盒.md` 的 SEC5（安装即信任）；`14-目标与支线.md` 的 GL 编号习惯。外部调研：

- `nix run`：构建并运行 installable（app 或 derivation），不装进 profile，产物进 Nix store，未被引用的路径由 GC 回收 —— <https://nix.dev/manual/nix/2.35/command-ref/new-cli/nix3-run.html>、<https://nix.dev/manual/nix/2.35/command-ref/new-cli/nix3-store-gc.html>
- `npx`：按需把包下载进 npm cache 后执行 bin，不全局安装，cache 复用以提速 —— <https://docs.npmjs.com/cli/v11/commands/npx>
- `go run`：解析依赖、编译到 build cache 后运行，不安装，cache 保留以加速后续 —— <https://pkg.go.dev/cmd/go>
- `docker run --rm`：退出即删容器，镜像留在本地缓存 —— <https://docs.docker.com/reference/cli/docker/container/run/>

## 范围

**做：**

- 一次性插件作为插件运行时的**执行模式**，复用 04 的 manifest 与进程托管。
- 生命周期：解析来源 → 拉取到临时目录 → 校验 manifest 与哈希 → 执行 → 收集产物 → 默认清理。
- 与常驻插件的关系：不注册工具、不占实例表；缓存可被 `gqy-clean --expired` 回收。
- 安全：沿用 SEC5「执行即信任」；来源显式指定、哈希校验防篡改。
- 对标 `nix run` / `npx` / `go run` / `docker run --rm`，给出 GQY 取舍。

**不做（后置）：**

- 插件市场与自动发现：来源只认显式指定，不自动搜索注册表。
- 一次性插件的细粒度权限 / 断网沙箱：与常驻插件一致，执行即信任（SEC5）。
- 跨运行状态保持：一次性插件每次运行无状态，不提供会话内共享状态。
- 签名验证（代码签名 / 供应链证明）：先做哈希校验，签名后置。
- 后台常驻式的一次性任务（daemon 化）：跑完即结束。

## 决定

### NX1 · 定位：执行模式，不是第二种插件格式

- 一次性插件不是新格式：manifest 与 04 P3 同源，只加 `mode` 区分。
- `mode` 缺省 = `resident`（常驻，装进 `$GQY_HOME/plugins/<id>`）；`mode: "oneshot"` = 一次性（拉到临时目录执行，跑完清理）。
- 常驻与一次性共用同一套适配器、生命周期与进程回收（04 P4 / P5 / P8）。

### NX2 · 来源解析与拉取

- 来源四类：本地路径、git 仓库（commit / tag）、URL（tarball / 单文件）、内置注册表条目。
- 解析到 `$GQY_HOME/tmp/oneshot/<id>-<run>`；`<run>` 是本次运行的唯一标识（时间戳 + 短随机）。
- 拉取后先校验 manifest（04 P3 全字段表）与哈希；任一步失败即弃，不执行。

### NX3 · 执行形态

- 两种执行入口：manifest 声明 `run` 动作 → 走 stdio JSON-RPC 的 `run`；未声明 → 直接跑 `command`。
- 输入：结构化参数或 stdin；输出：stdout、文件、结构化结果三选一或组合。
- 进程托管沿用 04 P8：独立进程组、超时杀组、stdin EOF 自退；一次性进程同样整组回收。

### NX4 · 生命周期与清理

固定顺序：

1. 解析来源（NX2）。
2. 拉取到 `$GQY_HOME/tmp/oneshot/<id>-<run>`。
3. 校验 manifest 与哈希。
4. 执行（NX3），带超时。
5. 收集产物（stdout / 文件 / 结构化结果）。
6. 默认删除工作目录；`--keep` 保留。
7. 结果写日志；失败同样清理（`--keep` 除外），退出码非 0 不进缓存。

### NX5 · 与常驻插件的关系

- 不注册进工具列表，不走 04 P11 的动作注册；执行期间也不占常驻实例表。
- 执行完不占用：工作目录默认删除，只有缓存（NX6）按需保留。
- 同一个 manifest 可以两种模式跑：装进 `$GQY_HOME/plugins/<id>` 是常驻，`oneshot` 是即用即弃。

### NX6 · 缓存与清理

- 缓存键 = 来源 + 版本 / 哈希；命中直接复用，未命中重新拉取。
- 缓存是派生数据（ST2），可重建；默认 TTL 7 天（对齐 05 S6），由 `gqy-clean --expired` 统一回收（ST7）。
- 缓存只为同版本重复执行提速，不是安装，不改变「一次性」语义。

### NX7 · 安全

- 执行即信任（SEC5）：一次性插件与常驻插件同权，能读、能写、能联网；不额外断网、不额外沙盒。
- 来源必须显式指定；manifest 或来源解析带哈希时强校验，防拉取过程被篡改；未带哈希时告警后执行。
- 拉取到的文件不自动执行：只有用户显式触发的一次运行才启动进程。

## 对标与取舍

| 工具 | 拉取 | 执行 | 清理 | 缓存 |
| --- | --- | --- | --- | --- |
| `nix run` | 按 installable 解析 flake | 构建后运行 app / derivation | 不装 profile；store 里未引用路径由 GC 回收 | Nix store 是全局缓存 |
| `npx` | 按需下载到 npm cache | 执行包 bin | 不全局安装 | npm cache 复用以提速 |
| `go run` | 解析依赖 | 编译到 build cache 后运行 | 不安装 | build cache 保留加速 |
| `docker run --rm` | 拉镜像（本地缓存） | 运行容器 | 退出即删容器 | 镜像留在本地 |
| GQY 一次性插件 | 拉取到 `$GQY_HOME/tmp/oneshot/<id>-<run>` | 复用 stdio JSON-RPC / command | 默认删工作目录，`--keep` 保留 | 按来源 + 哈希缓存，`gqy-clean --expired` 回收 |

取舍：GQY 本地优先，没有全局 store 也没有镜像仓库。最接近的是 `go run` 的「临时构建 + 缓存加速」，但 GQY 的产物是插件工作目录，所以把「缓存」降级为可选项、统一交给 `gqy-clean` 回收，不引入第二套清理机制。

## 数据样例

一次性插件 manifest（在 04 P3 基础上加 `mode` 与可选 `hash`）：

```json
{
  "id": "migrator",
  "name": "迁移器",
  "version": "1.0.0",
  "description": "把旧会话格式迁移到新格式，跑一次即可",
  "protocol": "gqy-jsonrpc-v1",
  "mode": "oneshot",
  "command": ["node", "index.js"],
  "hash": "sha256:…",
  "timeout_ms": 120000,
  "concurrency": "exclusive",
  "actions": [
    {
      "name": "run",
      "description": "执行一次性迁移",
      "schema": {
        "type": "object",
        "properties": {"source_dir": {"type": "string"}},
        "required": ["source_dir"]
      }
    }
  ]
}
```

## 验收

1. `mode:"oneshot"` 的 manifest 解析到临时目录，执行后工作目录被删；`--keep` 保留。
2. 哈希不匹配 → 拒绝执行，不进入缓存；manifest 非法 → 同样拒绝。
3. 声明 `run` 动作走 JSON-RPC `run`；未声明直接跑 `command`；超时杀整个进程组。
4. 一次性插件不注册进工具列表，不占常驻实例表；执行完 `/api/plugins` 无残留。
5. 同来源同哈希重复执行命中缓存；`gqy-clean --expired` 按 TTL 回收缓存。
6. 失败（退出码非 0）不写缓存，日志可查原因。

# 13 · 模型资料与选择器

依据：`00-设计理念.md` 的 G2（多供应商、可替换）；`01-架构.md` 的 D2（前端零构建 JS）；`02-网关与路由.md` 的 R6（模型解析）、C11 所在的 `/v1/models` 形状；`09-存储.md` 的 ST2（真相与派生）；`10-前端界面.md` 的 FE1（零构建）、FE3（设置页）、FE8（localStorage 边界）；`12-配置与热更新.md` 的 CF1/CF3（快照与热更新范围）。

## 范围

**做：**

- 模型资料从哪来：本机 `providers.json` 是权威；可选接入 models.dev 等公开目录做**补全与展示**（模型名、窗口、能力、价格）。
- 能力字段 `capabilities`：`tool_call` / `vision` / `thinking` / `reasoning_effort` / `context_window` / `max_output`，在 `/v1/models` 与前端展示中的字段形状。
- 前端模型选择器交互：搜索 + 过滤、分组、最近使用、默认标记、键盘导航、选择后立即生效。
- 后端支撑：`/v1/models` 扩展 `capabilities`；模型资料缓存与热更新。

**不做（后置）：**

- 用目录资料驱动路由决策：配置与路由仍只看 `providers.json`，资料只影响展示与提示。
- 供应商鉴权目录 / 自动同步订阅信息、精确计费：价格只做展示性参考。
- 服务端全量型号搜索 / 分页：单机模型数量小，前端过滤即可。
- 模型下载、本地部署信息：不是网关职责。
- 前端框架化：选择器遵循 FE1 零构建约束。

## 决定

### MD1 · providers.json 是权威，公开目录只做补全展示

- `providers.json` 的 `models` / `default_model` 决定「什么可路由、什么进 `/v1/models`」；目录资料不新增可路由模型、不覆盖配置。
- 可选接入 models.dev 等公开目录，只补展示字段：模型名、上下文窗口、能力、参考价格。
- 资料与配置冲突时以配置为准；资料缺失时前端标「资料未知」，不猜。

### MD2 · capabilities 字段形状

每个模型一份能力描述：

```json
{
  "tool_call": true,
  "vision": false,
  "thinking": true,
  "reasoning_effort": ["low", "medium", "high"],
  "context_window": 65536,
  "max_output": 8192
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `tool_call` | bool | 是否支持工具调用 |
| `vision` | bool | 是否支持图片输入 |
| `thinking` | bool | 是否输出思考过程 |
| `reasoning_effort` | string[] | 支持的思考力度档位；空数组 = 不支持 |
| `context_window` | int | 上下文窗口 token；0 = 未知 |
| `max_output` | int | 单次最大输出 token；0 = 未知 |

- 来源优先级：目录资料 → `providers.json` 显式覆盖（可选字段）→ 未知。
- 未知时展示「资料未知」，不影响路由（MD1）。

### MD3 · 资料是派生缓存，可重建

- CF 快照只含配置（12 CF1）；模型资料是配置之外的派生缓存，按 `provider/model` 键拉取后落盘。
- 缓存丢失或损坏可重建，不参与路由决策（09 ST2「删了它真相还在」）。
- 热更新：`providers.json` 变 → 重算「哪些模型需要资料」，按需补拉；目录资料按 TTL 刷新。

### MD4 · /v1/models 扩展 capabilities

- `data[]` 每项新增 `capabilities` 对象（MD2 形状）；`provider/model` 条目携带，路由组 `group/<id>` 不携带（组能力看成员）。
- 保持 OpenAI 兼容：`capabilities` 是 GQY 扩展字段，标准客户端忽略（同 C11 的 `display_name` / `members`）。
- 不返回密钥字段；参考价格放展示层，不进 `/v1/models` 必需字段。

```json
{
  "object": "list",
  "data": [
    {
      "id": "deepseek/deepseek-chat",
      "object": "model",
      "owned_by": "deepseek",
      "created": 0,
      "display_name": "DeepSeek Chat",
      "default": true,
      "capabilities": {
        "tool_call": true,
        "vision": false,
        "thinking": true,
        "reasoning_effort": ["low", "high"],
        "context_window": 65536,
        "max_output": 8192
      }
    },
    {"id": "group/daily", "object": "model", "owned_by": "group", "created": 0, "display_name": "日常",
     "members": ["deepseek/deepseek-chat", "moonshot/kimi-k2"]}
  ]
}
```

### MD5 · 前端模型选择器交互

- **搜索**：按模型名、provider 名、组名即时过滤。
- **过滤**：按能力（tool_call / vision / thinking）与供应商多选过滤。
- **分组**：provider 分组与路由组 `group/<id>` 两组；组内按 providers.json 顺序。
- **最近使用**：最近选择的 N 个置顶；存 localStorage（FE8 的 UI 偏好边界）。
- **默认标记**：`default: true` 的模型标「默认」，与最近使用区分显示。
- **键盘导航**：↑↓ 移动、回车选中、Esc 关闭；选择后立即生效，下一次请求用新模型。
- **零构建实现约束**：DOM 列表渲染 + 内存字符串 / 布尔过滤，无框架、无构建（FE1）。

### MD6 · 后端支撑：资料接口与缓存

- `/v1/models` 直接携带 `capabilities`（MD4），前端选择器一次请求拿到全部能力。
- 资料缓存落 `$GQY_HOME/cache/`（派生，可删重建）；目录拉取失败时沿用旧缓存，只影响展示。
- 离线：缓存命中即用；未命中只缺展示资料，路由照常（G1 本地优先）。

## 验收

1. 目录资料缺失时，`/v1/models` 仍列出 providers.json 的全部模型，能力字段标未知，不猜。
2. `capabilities` 六字段形状正确；路由组条目不带 `capabilities`，provider 模型条目带。
3. providers.json 显式覆盖某项能力时，以配置为准；目录资料不新增可路由模型。
4. 资料缓存删除后重建；providers.json 热更新后按需补拉资料，配置决策不受资料影响。
5. 前端选择器：搜索、能力 / 供应商过滤、分组、最近使用、默认标记、键盘导航、选择立即生效，零构建下可用。
6. `/v1/models` 不返回任何密钥字段。

# 19 · 运行时热加载

日期：2026-11-02
状态：已定（2026-11-02，实现落地）

## 问题

开关一个插件、换一次模型、改一行配置，都要重启服务——这在「千队并行」的场景里不可接受：重启会打断在途请求、丢掉会话里的运行状态，也让 WebUI 的操作变成摆设。

## 决定

### HR1 · 配置文件轮询热加载
`providers.json` / `routing.json` / `settings.json` 任一变化（mtime+size）→ 整份重新校验 → 原子切换快照 → 通知订阅者。默认 2s 轮询，不引入第三方依赖；配置写坏时**保留旧快照**并记录错误，等下一次修改再试。

### HR2 · 插件变化即重建工具表
插件的 load / unload / delete / scan 都会触发 `Manager.OnChange` → 服务端 `ResetExternal()` + `RegisterTools()`，模型**下一轮**就能看到新工具，无需重启。工具按 `Owned` 接口标记来源（`plugin:<id>`），重建只清插件工具，不碰核心工具。

### HR3 · 暴露策略热更新
- `settings.expose_external_tools`（默认 true）控制插件动作是否作为工具下发模型；改它立即生效。
- 单个插件可用 manifest 的 `"expose": false` 隐藏自己的全部动作。
- 环境变量 `GQY_ENABLE_EXTERNAL` 只在启动时兜底，不再是唯一开关。
- `/api/tools` 每项返回 `exposed`，前端/运维能看出「这个工具模型看不看得见」。

### HR4 · 不重启原则
所有热加载路径都**不重启进程**：配置切换是整份快照替换，插件是进程级加载/卸载，工具表是注册表重建。失败一律回滚到上一个可用状态（旧快照 / discovered）。

### HR5 · 模型选择的语义（两层）
- **每请求**：所有协议入口的 `model` 字段逐请求解析，天然热；在途请求不受影响。
- **全局默认**：`PUT /api/model/active {model, persist?}` 设一次覆盖，之后所有未指定 model 的请求（内部 loop 与外部 agent）都走它；`persist:true` 同时写回 `routing.json` 的 `default` 并热加载，重启仍生效。`GET /api/model/active` 返回 `model/source(config|runtime)/default`。
- 显式带 model 的请求仍优先；`group/<id>` 可设为覆盖但不持久化。

### HR7 · 持久连接（SSE）
`GET /api/events` 是一条 SSE 长连接：配置热加载、插件增删、全局模型切换都广播事件（`config` / `plugins` / `model`），15s 心跳保活。WebUI 据此刷新模型选择器、状态与插件页，不再轮询；慢客户端丢弃事件而不阻塞发布方。文件侧轮询默认 1s，可用 `GQY_CONFIG_POLL_MS` 调整（最小 100ms）。

### HR6 · 可观测
`/api/gateway/status` 的 `config.version` 反映热加载次数；`/api/tools` 的 `exposed`、插件 `source`/`read_only`、工具日志共同说明「谁现在能用什么」。

## 不做

- 插件进程内代码热替换（插件语言多样，不追这一层；改代码 = 卸载→加载）。
- 配置文件监听用 inotify/fsnotify（轮询足够，且零依赖；后续如需要可换）。
- 正在跑的 loop 中途换模型（一次对话内模型固定，避免上下文错乱）。

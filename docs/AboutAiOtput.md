# 关于ai输出问题
首先ai输出的有几大特点
- 套路句式：不是a，而是b
- 讨好腔调：稳稳的接住你
- 阿谀奉承：你太厉害了
- 空洞大词：赋能、闭环、抓手、底层逻辑
- 老师腔：这是什么？这是***

# 关于代码
- 最小mvp（这种不行，只能demo，因为让ai写的几乎都是生成项目，不存在mvp）
- 不够全面，不考虑性能
- 测试的标注过于全面，比如改动某个地方（前端）却跑后端的测试或者全量测试
- 高频使用的不能脚本化：例如软件版本号、软件发布流程等
- 遇到不会的不会去研究，不缺确定的时候不会询问用户
- 模块过于耦合
- 代码碎片零零碎碎的：比如放了tmp而不是项目里创建/tmp来统一管理和方便清理

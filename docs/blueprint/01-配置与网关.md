## 配置

### 来源与优先级

1. 进程环境变量与 `.env`（`LoadDotEnv` 只填充不存在的变量）。
2. `$GQY_HOME/providers.json`、`routing.json`、`settings.json`。
3. 内置默认值。

启动参数（`internal/config/env.go` 的 `Startup`）：`GQY_HOME`、`HOST`、`PORT`、`GQY_AUTH_TOKEN`、`GQY_WORKSPACE`、`GQY_TOOL_ROOTS`、`GQY_MOCK`、`GQY_ENABLE_EXTERNAL`、`GQY_API_BASE`、`GQY_API_KEY`、`GQY_API_UA`、`GQY_MODEL`、`GQY_RATE_LIMIT`。

### 默认值

| 字段 | 默认 |
| --- | --- |
| `HOST` / `PORT` | `127.0.0.1` / `5173` |
| `GQY_HOME` | `~/.gqy` |
| `routing.max_attempts` | 3（上限 5） |
| `routing.cooldown_seconds` | 30（上限 600） |
| `routing.queue_timeout_ms` | 1500 |
| `providers[].max_concurrency` | 2 |
| `settings.watch_enabled` | true（尚未接文件监视） |
| `settings.tool_timeout_s` / `shell_timeout_s` / `shell_allowlist` | 120 / 60 |
| `settings.upstream_timeout_s` | 120（范围 1–3600；每次上游调用整体超时，热更新生效） |
| `settings.stream_idle_timeout_s` | 60（范围 5–600；流式连续无新事件即中止） |
| `settings.expose_external_tools` | true（插件动作是否作为工具下发模型，热更新生效） |

### 校验

- provider：`id` 非空且唯一、`base_url` 非空且以 `http://` / `https://` 开头、`protocol` ∈ `openai-chat` / `anthropic-messages` / `gemini`、`default_model` 与 `models` 不同时为空、账号 id 唯一、`daily_token_limit` 非负。
- routing：组 id 唯一、`strategy` ∈ `order` / `rotate` / `usage`、`members` 非空且可解析、组引用无循环、上限不越界。
- settings：`rate_limit ≥ 0`、两个超时 > 0。

任何失败：启动时直接失败；重载时保留旧快照，错误写进 `Manager.Status().LastError`。

### 密钥

- 文件 `api_key` 优先；为空时读 `GQY_PROVIDER_<ID>_API_KEY`（id 大写、非字母数字转 `_`）。
- 环境变量 provider（`id=env`）使用 `GQY_API_KEY`。
- 明文只存在内存快照；`ProviderViews()` 只输出 `api_key_set`。

### 重载

`Manager.Reload()`：读三份文件 → 解析 → 校验 → `Build` 新快照 → `atomic.Pointer` 切换。版本号成功时 +1；失败不变。`POST /api/config/reload` 与 `SIGHUP` 走同一管线。文件监视（fsnotify）未实现。

## 网关运行时

### 一次请求

```
POST /v1/chat/completions
  → httpapi 鉴权 / 限流 / 请求 ID
  → chat.go: openai.DecodeChatRequest
  → gateway.Router.Complete / Stream
      → resolveOrdered: group 展开、策略排序
      → expandCandidates: provider → account，过滤 disabled / 配额 / 冷却
      → 亲和重排
      → 每个候选：并发槽 → adapter.Chat / Stream
      → 成功：记用量、亲和、请求日志
  → openai.EncodeChatResponse / SSE 帧
```

`/v1/messages` 与 `/v1beta/models/{model}:generateContent` 走同一条网关流程，只是入口解码与出口编码换成 Anthropic / Gemini 的适配器。

### 候选与策略

- `group/<id>` 递归展开；成员可以是 `group/<id>`、`<provider>/<model>`、裸模型名。
- 裸模型名只匹配 provider 的 `default_model`（R6）。
- `order`：配置顺序。
- `rotate`：每个组一个内存游标，每次请求前移一位；嵌套组各自旋转。
- `usage`：按成员「最近一次成功使用时间」升序，未用过的排前面。设计里的半衰期权重尚未实现。
- 去重键：`provider + "\x00" + model`。

### 账号与失败转移

- 每个 provider 的账号按配置顺序展开；`disabled` 跳过。
- 过滤顺序：配额耗尽（A7）→ 冷却中（R1/R3）→ 协议未注册。
- `max_attempts` 限制总尝试次数；4xx（除 429）不重试、不冷却；429 / 5xx / 连接 / 超时冷却 `cooldown_seconds`。
- 冷却中的账号直接不进入候选；全部不可用返回 `no_candidate`（503）。
- 并发：每账号一个带缓冲 channel 作为信号量，容量 `max_concurrency`；等待超过 `queue_timeout_ms` 返回 `queue_timeout`（503）。容量在首次创建后固定，改配置需重启才调整。
- 配额：内存态，UTC 自然日窗口；成功调用后累加 `prompt + completion` token；重启清零。
- 亲和：`X-GQY-Session`（或 `X-Session-Id`）→ `provider/account`，仅内存；命中且候选可用时排到最前。
- 流式切换边界：适配器产生第一个事件前可换候选；`emit` 被调用一次后不再切换，错误直接交还。

### 请求日志

`$GQY_HOME/gateway/requests.jsonl`，一行一次请求，字段：

`ts`、`request_id`、`session`、`provider`、`model`、`account`、`status`（`ok` / `error` / `no_candidate`）、`http_status`、`duration_ms`、`attempt`、`error_code`。

不落 prompt、回复正文、密钥。

## 协议适配器

`internal/provider`：

- `Request`：messages / tools / stream / max_tokens / temperature / top_p / stop。
- `Event`：`thinking` / `text` / `tool_call` / `usage` / `done`。
- `Error`：`Code`、`Retryable`、`HTTPStatus`、`Message`；`ClientStatus()` 映射对外状态码。
- `Registry`：协议名 → `Adapter`；空协议归一为 `openai-chat`；重复注册报错。

`internal/provider/openai`：

- 编码：messages、图片内容块、tools、tool_calls、stop、stream_options。
- 非流式解码：`content`、`reasoning_content`、`tool_calls`、`usage`、`finish_reason`。
- 流式：解析 `data:` 帧，累积工具参数，`[DONE]` 或 finish_reason 结束；usage 恰好发一次。
- 流始终向上游请求 `stream_options.include_usage=true` 以便配额记账；对外是否输出 usage 由客户端 `include_usage` 决定。

`internal/provider/anthropic`：

- 入口 `POST /v1/messages`；`system` 支持字符串与 blocks，`tool_use` / `tool_result` 映射内部工具调用，`thinking` 独立于 text。
- 出口流式事件族：`message_start` → `content_block_start` → `content_block_delta` → `content_block_stop` → `message_delta` → `message_stop`。
- `stop_reason` 映射到六种内部值；流式已开始后的错误帧细节未单测。

`internal/provider/gemini`：

- 入口 `POST /v1beta/models/{model}:generateContent` 与 `:streamGenerateContent`（`alt=sse`）。
- `systemInstruction`、`contents`、`functionCall` / `functionResponse`、`generationConfig` 映射到内部模型。
- `finishReason` / `usageMetadata` 映射；流式每帧是一个完整 `candidates` 增量。
- 模型名来自 URL，`encodeRequest` 不重复写 model。

## HTTP 层

- 鉴权覆盖 `/api`、`/v1`、`/v1beta`；`/api/auth` 与 `/healthz` 例外。
- 未设置令牌：只放行回环来源；非本机返回 403。
- 限流：`/api`、`/v1`、`/v1beta` 按连接对端 IP、分钟固定窗口；在鉴权外层。
- `POST /v1/chat/completions`：请求上限 32 MiB；非流式返回 `chat.completion`；流式返回 `data:` 帧 + `[DONE]`。
- `POST /v1/messages`：Anthropic Messages 形状；非流式与 `message_start` 事件族流式。
- `POST /v1beta/models/{model}:generateContent` / `:streamGenerateContent`：Gemini 形状；`alt=sse` 时流式。
- 响应头 `X-GQY-Provider`；流式在首帧前设置。
- 流式错误：首帧前返回 JSON 错误；首帧后写 `data: {"error":…}` 并断开。
- `GET /api/gateway/status`：配置状态、鉴权、限流、provider 安全视图、账号运行时状态、路由组。

## 已知偏差

1. `usage` 策略用「最近使用时间」近似设计里的半衰期用量，尚未实现 EWMA。
2. 文件监视 fsnotify 未接；只有手动重载与 SIGHUP。
3. 账号并发容量在首次创建后固定，热更新不重建；重启生效。
4. Anthropic / Gemini 的「流式已开始后补协议错误帧」细节未单测；适配器解析层有测试。
5. `/api/chat` 的五事件内部协议与会话落盘尚未实现。

### 租户（024）

`routing.json` 的 `tenants` 定义任务级隔离边界：

| 字段 | 含义 |
| --- | --- |
| `name` | 租户名（`[A-Za-z0-9_.-]{1,64}`），对应请求头 `X-GQY-Tenant` / `X-GQY-Task` |
| `max_concurrency` | 独立并发槽数（0 = 不单独限制） |
| `req_per_min` | 每分钟请求配额（0 = 不限），超限 429 `tenant_quota` |

请求先占租户槽（配额 + 并发），再占账号槽；`/api/gateway/status` 的 `tenants` 返回实时观测；`requests.jsonl` 每行带 `tenant`。

**全局默认模型与实时推送（027）**：`PUT /api/model/active {model,persist?}` 设一次覆盖，未指定 model 的请求（内部与外部 agent）都走它；`persist:true` 原子写回 `routing.json.default` 并热加载。`GET /api/events` 是 SSE 长连接，广播 `config`/`plugins`/`model` 事件；配置轮询默认 1s（`GQY_CONFIG_POLL_MS` 可调）。

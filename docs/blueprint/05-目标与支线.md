# 05 · 目标与支线

**状态**：已实现（2026-11-02，施工 011 / 013 落地）

**对应设计决定**：GL1–GL6（14-目标与支线）；另吸收 claude-code 走查的「独立评估器三态 + 错误分类」。

- GL1 goal 状态机：active / paused / completed / blocked，max_rounds 用尽转 blocked。
- GL2 主线优先：goal active 且 loop 在跑时，新指令不打断主线。
- GL3 支线两种形态：同会话排队消息、分叉会话（Branch 数据模型）。
- GL4 支线回报与合并：只有主线显式 adopt 才合并，不自动覆盖。
- GL5 中断与恢复：pause/resume，事件流重建。
- GL6 与 ask_user：主线挂起等答案，其他消息进支线。

### 主线抢占（施工 013）

- `/api/chat` 请求进入时：若存在 active goal **且** 该会话的 loop 正在跑（`Server.running`），消息入支线队列并返回 `{"ok":true,"queued":true,"goal":"…"}`，同时写 `branch` 事件；不静默丢弃。
- 入队幂等：`Manager.QueueOnce(goalID, messageID, message)` 按 messageID 去重；goal 非 active 时返回 false（走主线，不排队）。
- loop 每轮开始 **与轮末收尾前** 都执行 `drainBranches()`（轮末只执行排队支线，不注入采纳）：取走排队消息，每条走一次**独立的单轮模型调用**（不带工具、不改主线上下文），结果写成 `branch` 事件（`content`=原消息、`output`=支线回答）；失败记 `支线执行失败: …` 不拖垮主线（016）。
- 队列 FIFO：`TakeQueued(goalID)` 取走并清空。
- 支线登记与采纳（017）：执行完 `RegisterBranch(goalID, message, output)` 返回 `branch_id`；`POST /api/goal/{id}/adopt` 标记采纳；轮边界 `TakeAdoptions` 把摘要以 user 消息注入主线（前缀 `[支线已采纳，纳入主线考虑] `），每条只注入一次（`Branch.Injected`）。

### 评估器（`internal/goal/evaluator.go`）

- 三态：未达成 / 达成 / 不可能。
- 错误分类：不可恢复 → blocked；暂时性重试 3 次 → paused。

## 边角情况

- goal 非 active：新消息不排队，直接走主线（paused 时就是正常对话）。
- 同一 messageID 重复请求：只入队一次。
- max_rounds 用尽：置 blocked 并记录原因。
- 进程重启：`running` 标记是内存态，重启丢失；队列随 goal 保留，由下一次请求触发处理。
- 分叉会话：`Branch` 数据模型存在（branchID/parentID/summary/adopted），尚未写入会话 manifest（后续施工单）。

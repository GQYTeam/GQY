# 蓝图

蓝图写 GQY「现在到底长什么样」：每个格式、每条规矩、每种边角情况、每个端点的形状，以及它们由哪些测试守着、对应哪些代码。它是「设计决定」到「代码」之间的唯一中介：**设计一变先改蓝图，再改代码**（三层文档的分工见 `../README.md`）。

「当前实现」几页是随施工推进的聚合视图，按部件页是每部件的完整形状；两者不一致时，以「当前实现」为准，并把差异回写按部件页。

## 每页的固定结构

1. **状态**：待施工 / 部分 / 已实现 + 日期。
2. **对应设计决定**：列出本页兑现的编号。
3. **具体形状**：路径、schema、JSON/JSONL 样例、端点与字段。
4. **边角情况**：出错、空值、重复、并发、损坏等边界。
5. **由哪些测试守着**。
6. **对应代码**：`app/internal/...` 或「待建」。

## 历史代码的定位

当前工作树是重建起点，旧实现（`app/`）在 git 历史 `HEAD~2` 可参考。蓝图不照抄旧实现：以 `designs/` 的决定为准，旧代码只是事实线索。

# 插件运行时 + 多社区适配器 设计文档（纯文字版）

> 本文只讲"怎么干、为什么这么干"，不贴代码。适用于 Go 后端。

---

## 一、总体怎么干

一句话：**业务只认一个统一调用入口，核心层只认一个适配器契约，每个插件社区由一个适配器负责"翻译"，适配器下面挂的插件进程由运行时统一托底管理。**

分四层，依赖只能自上而下：

1. **业务层**：通过 `调用(插件ID, 动作, 参数)` 这一种方式使用所有插件，不关心插件来自哪个社区、是进程内库还是远程进程。
2. **运行时层（Manager）**：插件实例的注册表、生命周期状态机、并发控制、超时、可观测性、进程托底。所有"脏活"集中在这里。
3. **注册中心层（Registry）**：登记所有适配器，按"显式指定 → 社区名匹配 → 探测"三级策略选出适配器，歧义直接报错。
4. **适配器层（Adapter）**：每个社区一个适配器，负责把该社区的描述文件、调用协议、错误、能力"翻译"成核心统一模型；下面可以是进程内库、子进程、WASM、远程服务。

核心原则三条：

- **核心层不允许出现任何社区专有类型**。社区字段只存在于适配器内部。
- **适配器无状态、并发安全**；每个插件实例的状态放在"已加载插件"对象里。
- **新增一个社区 = 新增一个适配器包 + 跑一遍契约测试**，核心代码一行不改。这是判断架构是否成立的唯一标准。

## 二、并发怎么解决

并发问题拆成四类，分别有明确归属，不允许"到处加锁"。

### 1. 注册表并发

注册中心用一把读写锁保护适配器表。注册发生在启动阶段，读发生在每次加载，读多写极少，读写锁足够。**注册重复名必须报错**，不允许静默覆盖，否则排查成本极高。

### 2. 插件实例表并发

运行时的插件表同样读写锁保护。加载、卸载走写锁；调用走读锁。粒度是"表级"，不是"实例级"，因为实例数有限、操作快，表级锁足够简单可靠。

### 3. 单插件生命周期并发

每个插件实例内部有一把锁 + 一个状态机：加载中 → 就绪 → 关闭中 → 已关闭。

- 调用只在"就绪"状态放行，其余状态直接返回"未就绪"错误，不做等待。
- 卸载先置为"关闭中"（阻止新调用进入），再等在途调用结束，最后真正关闭。**关闭幂等**，重复卸载返回"未找到"，不 panic。
- 加载到一半失败，必须回滚：从表里摘除、释放已申请资源、关闭已启动进程。

### 4. 调用本身的并发

这是最需要讲清楚的一点。适配器层要声明它支持的并发模型，运行时按模型放行：

- **可并发型**（如 HTTP 远程插件、WASM 多实例）：直接并发调用。
- **单通道型**（如 stdin/stdout 子进程）：适配器内部维护"请求序号 → 等待通道"的多路复用表，多个调用并发写管道、按序号回收响应；或者适配器内部串行化队列。**这个选择由适配器做，运行时不管**。
- **独占型**（如有全局状态的原生库）：适配器内部加互斥锁，调用排队。

运行时统一给每次调用加超时与取消传播：超时到点，先取消上下文，再通知适配器"这次调用作废"；如果适配器是子进程，取消时要能中断或直接杀掉重启（见第六节）。

### 5. 优雅关闭的并发

收到退出信号后：先把运行时状态置为"关闭中"（拒绝新加载）→ 停止接受新调用 → 并行通知所有插件实例关闭（带总超时）→ 超时的实例强制销毁进程组 → 等待所有清理完成 → 进程退出。**任何一步都不允许无限等待**，必须有兜底超时。

## 三、远程怎么解决

"远程"在这里指两类：插件运行在**独立子进程**（本机），或运行在**远端服务**（跨机）。对业务层必须完全透明，都实现同一个"已加载插件"接口。

### 1. 传输层统一

不要每个适配器自己发明通信方式。核心层约定一个**最小传输契约**：请求-响应模型、请求带唯一序号、响应按序号匹配、错误带结构化码、支持取消。具体承载由适配器选：

- 本机子进程：首选标准输入输出上的 JSON-RPC（或长度前缀帧），零端口、零防火墙问题。
- 本机服务：Unix Domain Socket，权限可控、性能好。
- 跨机服务：gRPC over TCP/TLS，带认证。

适配器只依赖这个传输契约，不依赖具体插件社区。

### 2. 连接与健康

- 远程插件加载成功 = 连接建立 + 一次健康检查通过。健康检查不通过，加载失败。
- 调用期间区分"业务错误"和"连接错误"：连接错误触发重连（有限次数 + 退避），业务错误直接返回。
- 熔断：同一插件连续失败超过阈值，标记为"降级"，短时间内直接拒绝调用，避免拖垮上游。
- 每次调用带超时；超时后取消请求，不允许"发了不管"。

### 3. 远程与本地同一套错误模型

远程返回的原始错误必须在适配器内转换成统一错误（找不到、不支持、超时、权限、调用失败等）。业务层只看到统一错误码，不看到社区私有错误，也不看到网络层错误原文。

### 4. 远程的安全边界

- 跨机必须有认证（token / mTLS），不能裸奔。
- 远程插件声明的动作集合在加载时就固化，调用时先校验动作是否在清单内，再转发。
- 远程插件的资源限制（超时、并发上限、响应大小上限）在适配器里配置，运行时统一读取并执行。

## 四、适配怎么解决

适配器的职责边界要一次划清，后面就不再讨论。

### 1. 适配器负责什么

- **识别**：判断一个插件包属于本社区（只读、快速、无副作用、失败返回"不匹配"而不是报错）。
- **翻译描述文件**：把社区原始清单转成统一清单（ID、名称、版本、社区、协议版本、入口、权限、动作、通用元数据）。**社区私有字段一律不进统一清单**，需要透传的塞进通用键值元数据。
- **翻译调用**：统一动作名 + 统一参数（JSON 字节）→ 社区私有协议；返回值反向翻译。
- **翻译错误**：所有社区错误、网络错误、进程错误，统一转成结构化错误。
- **声明能力**：这个社区的插件支持哪些能力（同步调用、事件订阅、配置注入、热重载、沙箱、流式）。业务层先看能力声明，再做接口断言，两者都满足才调用。
- **声明协议版本区间**：加载前校验插件声明的协议版本是否落在区间内，不匹配直接拒绝，不等到运行时炸。
- **决定隔离方式**：进程内库、子进程、WASM、远程，由适配器决定，并如实写进能力声明。

### 2. 适配器不负责什么

- 不管插件实例表、不管生命周期状态机、不管并发调度、不管超时兜底、不管进程回收。这些全在运行时。
- 不直接调用业务代码。需要宿主能力（日志、配置、密钥、HTTP 客户端、数据目录）时，通过运行时注入的"宿主环境"拿，保证可测试、可替换。

### 3. 可选能力用"接口断言 + 能力声明"双校验

核心接口只保留最小集（识别、翻译清单、加载）。事件订阅、配置、热重载、流式这些做成可选接口。业务层调用前先查能力声明，再做接口断言，两者都满足才调用。**不要为了"统一"把核心接口做成大而全**，否则每个适配器都要实现一堆用不上的方法。

### 4. 版本与演进

- 社区协议大版本升级：新增一个适配器（如"社区A-v2"），新旧并存，旧的标记弃用，不原地改。
- 社区新增字段：适配器忽略未知字段，统一模型不动。
- 统一模型必须扩展时：优先走通用元数据或新增能力枚举，其次才是改结构，且必须向后兼容。
- 原则一句话：**社区协议怎么演进，都不推动核心模型演进。**

### 5. 选择策略不做隐式兜底

三级选择：显式指定适配器名 → 按社区名精确匹配（且版本兼容）→ 逐个探测。探测命中多个必须报错，要求调用方显式指定。**宁可报错，不靠注册顺序"猜"**，否则线上行为不可预期。

## 五、测试怎么解决

测试分五层，缺一层都会在生产环境还债。

### 1. 契约测试（最重要）

核心层提供一套"适配器契约测试套件"，每个适配器必须跑通。覆盖：识别成功/失败、清单翻译字段完整性、加载成功、调用成功、调用失败的错误模型、关闭幂等、协议版本不匹配被拒绝、并发调用不串包。新适配器只写"测试夹具"（一个真实插件包 + 期望输入输出），套件自动跑。这是保证"多适配器行为一致"的唯一低成本手段。

### 2. 适配器单元测试

针对翻译逻辑本身：清单字段映射、错误码映射、动作映射、版本区间判断。用表驱动，不依赖真实进程。

### 3. 集成测试

真实插件包 + 假宿主环境（假日志、假配置、临时数据目录），跑完整"加载 → 调用 → 卸载"链路。每个适配器至少一个真实包样例。

### 4. 进程与故障测试（针对子进程/远程适配器）

- **孤儿进程测试**：启动插件进程后，让父进程（测试进程）异常退出，断言插件进程在限定时间内自行退出，不残留。这是必测项。
- **超时测试**：插件故意不响应，断言调用超时后进程被清理、资源被回收。
- **崩溃测试**：插件进程中途退出，断言运行时检测到退出、状态变为不可用、不无限重启。
- **管道断裂测试**：关闭管道，断言双方都能感知并退出。
- **僵尸进程测试**：反复加载卸载，断言没有僵尸进程累积（检查进程状态）。

### 5. 并发与竞态测试

- 开竞态检测跑：并发加载同一插件、并发调用、加载与卸载交错、卸载与调用交错。
- 断言：重复加载被拒绝、卸载幂等、调用不会打到已关闭实例、无数据竞争报告。
- 压测：固定并发数下调用延迟与错误率稳定，不随运行时间劣化（验证无泄漏）。

另外建议加**故障注入**：网络抖动、响应慢、返回畸形数据、进程被杀，验证适配器和运行时的容错路径。

## 六、进程怎么管：用完就丢，且不产生孤儿

这是全文最关键的一节。策略是：**每个插件实例对应一个受控进程（或进程组），生命周期完全归运行时所有；卸载即销毁，不复用；销毁有分级兜底；父进程任何形式的退出都能带走子进程。**

### 1. 启动：从第一秒就为"能干净杀掉"做准备

- **独立进程组**：启动时把插件进程放进它自己的进程组（本机 Unix 系用 setpgid）。这样插件自己再 fork 的子进程也在同一组里，将来可以整组杀。
- **标准输入作为生命线**：插件的标准输入由父进程持有。父进程一旦消失，管道关闭，插件读到 EOF 应自行退出。**这是最后一道防线，要写进插件协议规范并要求适配器实现。**
- **父死子亡信号**（Linux 可选增强）：设置 PR_SET_PDEATHSIG，父进程死亡时内核直接给子进程发信号。作为第二道防线。
- **Windows 差异**：用 Job Object 把进程树绑在一起，父进程退出时整棵树被销毁；或用带 /T 的 taskkill 杀整棵树。适配器负责屏蔽平台差异。
- **工作目录与临时资源**：每个实例一个独立临时目录、独立 socket 路径、独立日志文件，销毁时整目录删除，避免残留。

### 2. 运行：常驻监控

- 启动后立刻起一个等待协程，阻塞在"等待进程退出"上。进程一退出，立刻：更新状态为不可用、记录退出码与原因、清理关联资源、通知所有在途调用失败。
- **崩溃不无限重启**：允许有限次数的自动重启（比如 3 次，带退避），超过就标记为"失败"，等人工或下次显式加载。**不允许"重启风暴"**。
- **心跳/看门狗**：父进程定期向插件写心跳帧；插件超过 N 个周期没收到心跳就自行退出。适用于远程和子进程两类。注意：心跳是补充手段，不是替代生命线。

### 3. 关闭：分级兜底，绝不无限等

卸载或进程退出时的关闭顺序，固定为：

1. 置状态为"关闭中"，拒绝新调用。
2. 等在途调用结束（带短超时）。
3. 走优雅关闭：发关闭请求（或 SIGTERM），等插件自行退出（带超时，比如 5 秒）。
4. 超时未退：对整个**进程组**发强制终止信号（不是只杀主进程），确保子树一起走。
5. 再等一小段时间，仍未退：升级为不可中断的强杀（SIGKILL 整个进程组）。
6. 回收：等待协程已回收进程（避免僵尸）、删除临时目录、关闭管道与文件句柄、删除 socket 文件。
7. 从实例表摘除。

**关键点：杀的是进程组，不是单个 PID。** 只杀主进程是孤儿进程的头号来源——插件自己起的子进程会变成孤儿。这一步必须由运行时统一做，不能交给适配器各自实现。

### 4. 父进程自己退出时

运行时注册退出信号处理：收到中断/终止信号，走一遍"全部插件优雅关闭 + 强杀兜底"的流程，然后再退出。同时，即使信号处理没来得及跑（比如被强杀），还有两层兜底：插件读标准输入 EOF 自杀、父死子亡信号 / Job Object。

### 5. 父进程崩溃（连信号处理都没跑）

这是"孤儿进程"的典型场景，靠三层兜底：

- 第一层：标准输入 EOF（跨平台，最可靠，但要求插件协议实现）。
- 第二层：父死子亡信号（Linux）/ Job Object（Windows），内核级，父进程一死立刻生效。
- 第三层：插件侧心跳超时自杀（兜底兜底）。

三层任意一层生效即可，实际部署时至少保证前两层。

### 6. "用完就丢"的代价与边界

- **收益**：无状态残留、无内存泄漏累积、版本隔离彻底、崩溃影响面最小、实现简单。
- **代价**：冷启动开销。应对方式：加载后预热、把"加载"和"首次调用"解耦、对高频插件允许适配器声明"进程常驻"并在能力里体现。
- **边界**：不管是否常驻，**卸载即销毁、销毁即整组回收**这条规则不变。常驻只是"存活时间长"，不是"不复用就泄漏"。

### 7. 幂等与可观测

- 关闭必须幂等：重复卸载返回"未找到"，不报错、不 panic、不重复杀。
- 进程相关事件全部打点：启动、退出码、重启次数、强杀次数、僵尸回收次数、孤儿兜底触发次数。**"孤儿兜底触发"这个指标一旦非零，说明前面某层防护失效，要告警。**

## 七、落地顺序

1. 定统一模型 + 适配器契约 + 注册中心 + 运行时骨架，接**第一个**真实社区，跑通"加载/调用/卸载/进程回收"。
2. 抽契约测试套件，让第一个适配器跑通全部契约，并把"孤儿进程测试"纳入 CI。
3. 接**第二个**社区，验证核心零改动。这是架构成立的判据。
4. 补远程适配器（Unix Socket / gRPC）、熔断、重连、心跳。
5. 补可观测性、权限、资源限制、故障注入测试。
6. 可选：适配器本身可动态加载，实现"适配器也可插拔"。

## 八、一句话总结

- **并发**：适配器无状态、实例持状态、表级读写锁、单插件状态机、调用并发模型由适配器声明、超时取消统一兜底、关闭幂等且分级兜底。
- **远程**：传输契约统一、连接健康检查、错误统一转换、认证与熔断、业务层无感。
- **适配**：最小接口 + 可选接口 + 能力声明双校验、私有字段不出适配器、版本区间前置校验、探测歧义报错、社区演进不推动核心演进。
- **测试**：契约测试保一致、单元测试保翻译、集成测试保链路、进程故障测试保不残留、并发竞态测试保稳定。
- **进程**：独立进程组、杀组不杀单进程、标准输入生命线 + 父死子亡信号 + 心跳三层兜底、关闭分级超时、卸载即销毁、全链路打点，"孤儿兜底触发"必须为零。

# 2026-11-02 · 端到端冒烟（mock 上游，历史记录）

目的：在没有真实模型 key 的前提下，把「HTTP → 网关 → 上游 → agent loop → 工具 → SSE → 落盘」整条链路跑一遍，验证施工 001–013 拼起来是否真的可用。

## 环境

- mock 上游：`scripts/e2e-mock/mock_upstream.py`（最小 OpenAI 兼容服务，第一轮返回 `read` 工具调用，第二轮返回文本）。复现步骤见该目录 `README.md`。
- 服务：`GQY_HOME=<临时目录>`、`GQY_WORKSPACE=<临时工作区>`、`HOST=127.0.0.1`、无 `GQY_AUTH_TOKEN`（回环放行）。
- provider：`mock`（openai-chat，base_url 指向 mock），routing 默认 `mock/mock-1`。

## 覆盖与结果

| 链路 | 验证方式 | 结果 |
| --- | --- | --- |
| `/healthz` | curl | `{"status":"ok",...}` ✅ |
| `/v1/chat/completions` 流式 | curl -N | 帧序：role → `tool_calls`（read + arguments）→ finish_reason `tool_calls` → `[DONE]` ✅ |

| 请求日志 | `gateway/requests.jsonl` | 每行含 provider/account/model/status/duration_ms；一次 loop 两次上游调用各一行（同一 request_id）✅ |
| `X-GQY-Provider` | 响应头 | `mock/a1` ✅（本轮修复后才出现，见下） |
| `X-GQY-Session` | 响应头 | 会话 id ✅ |
| 会话 manifest | `manifest.json` | `workspace` 正确记录工作区 ✅（本轮修复） |

## 本轮发现并修复

1. **`/api/chat` 不带 `X-GQY-Provider`**（违反 02 R4）：`handleAgentChat` 构造 `gateway.Meta` 时没有 `OnSelect`，只有 `/v1/chat/completions` 有。
   修：给 `/api/chat` 的 Meta 加 `OnSelect`，在首个事件写出前设置响应头。
2. **会话 manifest 的 `workspace` 为空**（违反 05 S1）：`store.Create("")` 传了空串。
   修：创建会话时传 `snap.Workspace`。

## 观察（未改，记为现状）

- 一次 agent loop 对上游的**每次调用**各写一行请求日志（同一 `request_id` 多行）。R7 的「一行一请求」在工具循环场景下应理解为「一行一次上游调用」；如需按请求聚合，后置到日志聚合。
- mock 上游第一轮返回 `tool_calls` 时没有 `content`，透传路径正确处理。
